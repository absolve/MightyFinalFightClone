# 玩家基本动画配置表

> 目的：把「玩家到底需要哪些动画」一次性定死。名字是代码契约（改了代码就找不到片段），
> 帧数与贴图由人工在 `data/sprites/<角色>_frames.tres` 里配。
> 本文的贴图内容是按 `sprite/player/*.png` 逐帧目视确认的，行号 = 原精灵表的 y 偏移。

---

## 1. 命名契约：谁在播哪个动画

代码里写死的动画名只有下面这些。**只有这些名字需要存在**，其它名字不会被任何逻辑引用。

| 动画名 | 播放者 | 触发 | 缺失后果 |
|---|---|---|---|
| `default` | `idle_state.gd:8` | 地面待机 | 待机无画面（必须） |
| `walk` | `walk_state.gd:12` | 按住方向 | 走路无画面（必须） |
| `jump` | `jump_state.gd:8` | 上升段；同时是所有空中片段的兜底 | 空中全程无画面（必须） |
| `fall` | `jump_state.gd:9`、`idle_state.gd:12` | 下落段 | 退回 `jump`（建议有） |
| `jumpRoll` | `jump_state.gd:11` | 按住方向起跳，全程 | 退回 `jump`（建议有） |
| `jumpAttack` | `jump_state.gd:12` | 空中按拳 | 空中攻击无画面（必须） |
| `jumpKick` | `jump_state.gd:13` | 空中按 下+拳 | 退回 `jumpAttack`（建议有） |
| `hurt` | `hurt_state.gd:23` | 被打 | 受击无画面（必须） |
| `act1` | `attack_state.gd:42` | 第 1 段；同时是蹲击的兜底 | 出拳无画面（必须） |
| `act2` | `attack_state.gd:42` | 第 2 段（需第 1 段命中） | 退回 `act1` 的时长，连段手感变差（必须） |
| `act3` | `attack_state.gd:42` | 第 3 段（需第 2 段命中） | 同上（必须） |
| `squatAttack` | `attack_state.gd:39` | 下+拳 | 退回 `act1`（建议有） |
| `act4` / `act5` / `act7` | `skill_state.gd:19-20` | 搓招必杀，经场景里的 `skillAnims` 映射 | 全部退回 `act4`（三个必杀至少要有一个） |

场景侧的映射（`scene/player/<角色>.tscn` 的 `skillAnims`，三人当前一致）：

| 必杀 | 输入 | 动画 | 原作对应 |
|---|---|---|---|
| `skill1` | 方向 + 拳 | `act5` | 特殊技（Cody Tornado Sweep / Guy Sonic Kick / Haggar 冲撞） |
| `skill2` | ←→ 或 →← + 拳 | `act4` | 必殺技 A+B（Super Kick / Whirlwind Kick / Spinning Clothesline） |
| `skill3` | ↑↓ + 拳 | `act7` | 第二特殊技（Cody Rising Uppercut / Guy Fire Kick / Haggar 手刀） |

**代码零引用、已从三人 SpriteFrames 删除的名字**（2026-11）：`down2`、`knockAway`、`tumbleDown`。
（玩家没有倒地/起身状态机，`down`、`wake`、`grap`、`throw`、`squat` 目前也没有玩家侧播放者，
但它们对应原作真实存在的动作，抓取与倒地系统落地后要接线，所以保留定义。）

删除后各角色的动画名数量：Cody 18（其中 `down` 是 0 帧占位，等倒地系统接线时填帧）、
Guy 20、Haggar 20。Cody 还缺 `squatAttack` 与 `act7` 两个契约名，配帧时新建即可。
`script/cody.gd` 里那份 `RESERVED_OVERRIDES`（`act8`~`act12`，没有任何代码引用）也一并删了，
`squatAttack` / `act7` 合并进 `MOVE_OVERRIDES`，三人现在都是单一一张覆盖表。

**空动画是静默失效的**：`anim_builder.gd:79` 与 `:90` 会跳过 `frame_count == 0` 的片段，
`hasAnim()` 随之返回 false，走上面的「缺失后果」列。所以「留个空名字占位」等于没有。

## 2. 参数在哪里改

- **帧 → 贴图**：只改 `data/sprites/<角色>_frames.tres`（SpriteFrames 编辑器）。
- **fps / loop / 命中窗口**：改 `script/<角色>.gd` 的 `MOVE_OVERRIDES`，**不是**改 SpriteFrames。
  SpriteFrames 里每个动画的 `speed` / `loop` 字段 AnimBuilder 完全不读，改了没效果。
- 一次性片段（招式、倒地、起身）在 `MOVE_OVERRIDES` 里**不要写 `"loop": true`**；
  只有需要持续播放的（`default` / `walk` / `jump` / `fall` / `jumpRoll` / `squat` / `grap`）才循环。
  本轮已把 Cody/Guy/Haggar 的 `down`、`wake` 从循环改成不循环。
- `hitWindow` 必须小于片段时长（`帧数 / fps`），越界会 `push_warning` 并被自动收窄
  （`anim_builder.gd:136-143`）。**加帧/删帧后要回头核对窗口。**
- 配完必须重跑生成工具，否则运行期用的还是旧动画库：
  打开 `scene/player/<角色>.tscn` → 运行 `script/editor/anim_build_tool.gd` → 保存场景。
  它会覆盖 `data/anims/<角色>_library.tres` 与 `<角色>_state_machine.tres`。
- **只有 Cody 有逐帧判定框数据**：`data/shapes/cody_hurt_shapes.tres`（受伤框）与
  `data/shapes/cody_hit_shapes.tres`（攻击框）按动画名存了一个数组，**数组长度必须等于帧数**。
  改帧数时这里要同步增删，否则越界的帧会取到 `null`，判定框静默退回场景里的默认形状
  （受伤框 26×40、攻击框 18×16），表现为「某一帧突然变回站立框」。
  Guy / Haggar 没有挂 `shape_frames`，用的是场景里的单一形状，改帧数不影响判定。
- 动画名增删也要同步上面两个 `data` 字典的键；键多于片段是死数据，键少于片段会走默认形状。

## 7. 配置完怎么验

```
/f/Godot_v4.7.2-stable_win64_console.exe --headless --path MightyFinalFight --import
/f/Godot_v4.7.2-stable_win64_console.exe --headless --path MightyFinalFight --fixed-fps 60 res://test/<对应测试>.tscn
```

看两件事：

1. **没有 `hitWindow ... 超出片段长度` 警告** —— 有就说明帧数和 `MOVE_OVERRIDES` 里的窗口不匹配。
2. **没有 `hasAnim` 退化** —— 空中按拳、下+拳、搓招出的动作要和预期一致；
   如果 `jumpAttack` 之类缺失，代码会静默退回 `jump`，画面表现为「空中出拳没动画」。

帧与动作是否对应，最终只能目视：在 Godot 里打开 `data/sprites/<角色>_frames.tres`，
逐个动画名点播放，对照本文 §3.1 / §4.1 / §5.1 的内容描述。
