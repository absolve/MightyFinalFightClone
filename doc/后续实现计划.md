# Mighty Final Fight Clone - 后续实现计划

> 本文档基于《项目现状.md》的盘点结果，规划从当前「早期脚手架」推进到「可玩 Demo」再到「完整复刻」的开发路线。
> 原作参考：NES《快打旋风》(Mighty Final Fight, Capcom 1993)，横版清版动作游戏。

## 开发原则

1. **先打通最小可玩闭环**：移动 → 攻击 → 命中 → 敌人受伤 → 死亡。先纵向跑通一条线，再横向铺功能。
2. **复用既有框架**：状态机、object 基类、SpriteFrames 动画已就位，优先在现有结构上填肉，不另起炉灶。
3. **数据驱动**：角色数值、敌人波次、关卡配置尽量走资源文件（Resource/JSON），便于后续扩展（呼应 user_profile 中 Spring Data JPA 的「数据驱动」偏好）。

## 优先级建议

| 优先级 | 阶段 | 理由 |
|--------|------|------|
| P0 | 1 + 2 | 没有可玩的攻击命中，后续一切无从验证 |
| P1 | 3 + 5 | 有敌人可打、有 HUD 看血量 = 最小可玩 Demo |
| P1 | 8 | 音频与战斗强相关，越早接入手感越好 |
| P2 | 4 + 6 | 关卡推进让 Demo 变成「一关游戏」 |
| P2 | 7 | Boss 是关卡高潮 |
| P3 | 9 + 10 | 元流程与打磨，影响「成品感」 |
