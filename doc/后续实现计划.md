# Mighty Final Fight Clone - 后续实现计划

> 本文档基于《项目现状.md》的盘点结果，规划从当前「早期脚手架」推进到「可玩 Demo」再到「完整复刻」的开发路线。
> 原作参考：NES《快打旋风》(Mighty Final Fight, Capcom 1993)，横版清版动作游戏。

## 开发原则

1. **先打通最小可玩闭环**：移动 → 攻击 → 命中 → 敌人受伤 → 死亡。先纵向跑通一条线，再横向铺功能。
2. **复用既有框架**：状态机、object 基类、SpriteFrames 动画已就位，优先在现有结构上填肉，不另起炉灶。
3. **数据驱动**：角色数值、敌人波次、关卡配置尽量走资源文件（Resource/JSON），便于后续扩展（呼应 user_profile 中 Spring Data JPA 的「数据驱动」偏好）。

## 阶段路线图

### 阶段 1：玩家核心闭环（移动 + 动画 + 状态机）
**目标**：让 Cody/Guy/Haggar 能在场景中行走、跳跃、切换动画。

- [ ] 重构 `playerState.gd`，拆分为多个子状态：
  - `idleState`：静止，监听移动/攻击/跳跃输入
  - `walkState`：移动，按方向播放 walk 动画
  - `jumpState`：起跳→空中→落地，接现有 zVec 重力逻辑
  - `attackState`：出拳连段（act1/act2/act3 对应 3 连击）
  - `hurtState`：受击硬直
  - `hitFlyingState`：被击飞倒地
  - `skillState`：必杀技
- [ ] 在 `stateMachine.gd` 实现 `transition_to(state_path, data)` 方法，驱动状态切换。
- [ ] `object.gd` 增加 `faceDir`（朝向）字段，控制贴图翻转。
- [ ] 移动时按 `vec` 切换 walk/idle 动画；跳跃切换 jump 动画。
- [ ] 移除 `playerState.gd` 中的 `print(player.zVec)` 调试残留。

### 阶段 2：战斗系统
**目标**：出拳能命中敌人，敌人能掉血。

- [ ] 给 `object.tscn` 的 `hurtBox` / `hitBox` 填充 `CollisionShape2D`（RectangleShape2D），设置合理尺寸并启用 layer/mask：
  - hitBox：layer = `playerHitBox`，mask = `enemy`
  - hurtBox：layer = `enemyHitBox`，mask = `enemyHitBox`
- [ ] `object.gd` 增加 `hp`/`maxHp`/`attack`/`invincibleTimer` 管理与 `takeDamage(dmg, fromDir)` 方法。
- [ ] 攻击状态期间启用 hitBox，监听 `area_entered` / `body_entered` 判定命中。
- [ ] 命中后调用被击方 `takeDamage`，触发 `hurtState` 或 `hitFlyingState`（按伤害类型）。
- [ ] 实现连段计数：3 连击后接击飞。
- [ ] 实现 Grab/Throw（grap/throw 动画）：靠近敌人按键触发抓取，再按键投掷。

### 阶段 3：敌人系统
**目标**：场景中出现敌人并能被击败。

- [ ] 新建 `script/enemy.gd`（`extends object`），实现基础敌人：巡逻→追击→攻击玩家。
- [ ] 抽象出 `enemyState.gd` 及子状态（idle/pursue/attack/hurt/dead）。
- [ ] 新建 `script/enemyFactory.gd` 或 `scene/enemy.tscn`，按类型实例化敌人（沿用 sprite/enemy 资源）。
- [ ] 敌人死亡：播放倒地动画 → 移除节点 → 掉落概率生成道具。
- [ ] 在 `stage1.gd` 写入测试用敌人刷新，验证战斗闭环。

### 阶段 4：关卡推进系统
**目标**：关卡可滚动、按波次刷怪、推进到 Boss。

- [ ] `map.gd` 增加摄像机/背景滚动逻辑（玩家接近屏幕右侧时滚动 bg）。
- [ ] `stageManage.gd` 实现关卡状态机：当前波次 → 清场检测 → 下一波 → Boss → 关卡结束。
- [ ] 用 Resource/JSON 定义每关波次（敌人类型、数量、坐标、触发条件）。
- [ ] 实现关卡切换（`nextStage` 字段已预留）。
- [ ] 至少完成 Round 1 的完整流程（含结尾 Boss）。

### 阶段 5：HUD 与 UI
**目标**：玩家看得见血量、分数、命数。

- [x] 新建 `scene/hud.tscn` + `script/hud.gd`（CanvasLayer）：
  - 玩家血条（沿用 sprite 中 HUD 贴图）
  - 敌人血条（Boss 专用）
  - 分数、命数、计时器
- [ ] 实现选人画面 `scene/characterSelect.tscn`：展示 Cody/Guy/Haggar，按键确认。
- [ ] 打通 `welcome.gd`：按 Start → 选人 → 进入 stage1（当前暂直连 stage1）。
- [ ] 暂停菜单（Esc）。

### 阶段 6：道具与拾取
**目标**：敌人掉落道具，玩家可拾取回血/加分/获得武器。

- [ ] `item.gd` 完善 `type` 枚举（food/weapon/bonus/special）。
- [ ] `item.tscn` 填充 CollisionShape2D 与动画。
- [ ] 玩家 `area_entered` 检测道具，调用对应效果（回血、加分、装备武器改变攻击）。
- [ ] 武器系统（刀/棍/油桶）作为攻击状态变种。

### 阶段 7：Boss 战
**目标**：每关结尾有 Boss，有独立行为模式。

- [ ] 新建 `script/boss.gd`（`extends enemy`），实现 Boss 专属 AI（多阶段、大招）。
- [ ] 沿用 `sprite/enemy/Bosses_*.png` 资源，为每个 Boss 配置 SpriteFrames。
- [ ] Boss 血条 UI、出场过场。

### 阶段 8：音频系统
**目标**：BGM + 音效全面接入。

- [ ] 新建 `autoload/audio.gd`（Autoload 单例），封装 `play_sfx(name)` / `play_bgm(name)`。
- [ ] 声音资源映射：出拳→出拳.wav、击中→击中.wav、起跳→起跳.wav、落地→落地.wav 等。
- [ ] `map.gd` 的 `bgMusic` 字段接入 BGM 播放。
- [ ] 各状态/事件回调音效（攻击、命中、跳跃、倒地、死亡、必杀）。

### 阶段 9：过场与元系统
**目标**：完整的开始→游戏→结束流程。

- [ ] 关卡间过场（沿用 sprite/Cutscenes 贴图）。

### 阶段 10：打磨与扩展
**目标**：达到原作完成度。

- [ ] 必杀技：Cody/Guy/Haggar 各自的特殊招式（旋风腿、倒勾脚、dragon_fist、光波）。
- [ ] 角色数值差异化（速度/攻击/血量/招式）。

## 优先级建议

| 优先级 | 阶段 | 理由 |
|--------|------|------|
| P0 | 1 + 2 | 没有可玩的攻击命中，后续一切无从验证 |
| P1 | 3 + 5 | 有敌人可打、有 HUD 看血量 = 最小可玩 Demo |
| P1 | 8 | 音频与战斗强相关，越早接入手感越好 |
| P2 | 4 + 6 | 关卡推进让 Demo 变成「一关游戏」 |
| P2 | 7 | Boss 是关卡高潮 |
| P3 | 9 + 10 | 元流程与打磨，影响「成品感」 |
