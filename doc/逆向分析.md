# Mighty Final Fight (U) 静态逆向分析

> 分析对象：`E:\Mighty Final Fight (U).nes`（md5 `1355eccce09d3e9554ff9120387f64b0`）
> 工具：`tools/re/dis6502.py`（6502 反汇编）、`tools/re/mff_banked.py`（带换 bank 上下文的追踪器）
> 输出：`tools/re/out/bank**.asm`（带标签、调用者、跳转表标注的反汇编清单）

## 1. ROM 概况

| 项 | 值 |
| --- | --- |
| Mapper | 4（MMC3） |
| PRG | 128KB = 16 × 8KB |
| CHR | 128KB |
| 镜像 | 水平 |
| 固定 bank | bank 14 → `$C000-$DFFF`，bank 15 → `$E000-$FFFF` |
| 可切换 bank | `$8000-$9FFF` = R6，`$A000-$BFFF` = R7 |

MMC3 固定映射意味着 `$C000` 以上永远可见，游戏引擎主体都在这里；关卡/场景数据放可切换 bank。

## 2. 换 bank 约定（静态确认）

```
RAM $F4 = 当前 $8000 窗口的 PRG bank (R6)
RAM $F5 = 当前 $A000 窗口的 PRG bank (R7)
写 $F4/$F5 → JSR $FF4D 生效 → JSR/JMP $8000 或 $A000 进入对应 bank
```

例：`$C556`（启动任务）里 `LDX #4 / STX $F4 / INX / STX $F5 / JSR $FF4D / JSR $8000`。
追踪器就是靠这个约定把 banked 跳转解析成 (bank, offset)。

另：MMC3 用 `$8000` 选寄存器、`$8001` 写值；CHR 的 bank 号缓存在 `$E8-$ED`，NMI 每帧恢复（`$C08E`、`$C0BA`）。

## 3. 中断与帧流程

| 入口 | 地址 | 作用 |
| --- | --- | --- |
| NMI | `$C000` | 调色板上传（`$0600`→`$3F00`）、VRAM 队列（`$0780`，格式 `hi,lo,len-1,data…` 以 bit7 结尾）、OAM DMA（`$0200`→`$4014`）、恢复 CHR bank、设置 MMC3 扫描线 IRQ |
| RESET | `$FE00` | 初始化硬件/RAM/任务槽，最后进入任务调度循环 `$FEBD` |
| IRQ | `$C13B` | MMC3 扫描线中断；`JMP ($009C)`，指针由 NMI 指向 `$C14A` 起的滚动分段处理 |

主循环在任务 0（入口 `$C556`）：初始化 → 标题/演示循环 → 按 Start 进入战斗 → 每帧 `$C8ED`，用 `JSR $FF31` 让出到 NMI，`$EE` 是帧标志。

## 4. 任务系统（协程）

`$80-$8F` 共 4 个槽，每槽 4 字节：

| 偏移 | 含义 |
| --- | --- |
| `$80,X` | 状态（≥4 有效；8 = 直接 `JMP (ptr)`；4-7 = 用 `$82,X` 当栈指针 `TXS` 后 RTS 进入） |
| `$81,X` | 计时器（NMI 每帧递减） |
| `$82,X` / `$83,X` | 任务入口低/高字节 |

辅助例程：`$FF02` 启动任务、`$FF31` 等待 NMI（yield）、`$FF2A` 延时 N 帧、`$FF26` 槽号×4。
调度循环：`$FEBD`（复位后）与 `$FEF2` 的 `TXS` 切换栈。

## 5. 输入

`$C279` 每帧轮询两个手柄：

| 地址 | 含义 |
| --- | --- |
| `$14` / `$15` | P1 / P2 **本帧新按下**（边沿） |
| `$16` / `$17` | P1 / P2 **当前按住** |
| `$00` / `$01` | 轮询临时值（勿用） |

位序（轮询先读 A，`ROL` 左移 8 次后首位于 bit7）：**bit7=A, bit6=B, bit5=Select, bit4=Start, bit3=Up, bit2=Down, bit1=Left, bit0=Right**。
示例：`$C904` 判断 `$14 & #$10` = Start 边沿；`$C2B7` 屏蔽同轴对按（`AND #$0C`=上下、`AND #$03`=左右）。

## 6. 游戏模式与分派表

`RAM $30` = 游戏模式 id。每帧 `$C93B` → `$C9B6` 按 `$30` 查表分派：

```
$C9B6: LDY $30
       LDA $C9CA,Y -> $00      ; 低字节表
       LDA $C9F5,Y -> $01      ; 高字节表（43 项）
       JMP ($0000)
```

表项（前 16 项）：`$CA20 $CF88 $D2B7 $D30F $D7A3 $D9FA $DA3F $DE5E $CCB4 $DC6C $D45A $DCDD $DD6A $CCB4 $DE5E $CCB4`。
大量模式共用 `$CCB4`（默认空处理）。各模式处理代码集中在 bank 14 `$CA20-$DE5E`。

另有 bank 0 的每帧二级分派：`$8000` 表 `$8011/$803B`（42 项，索引同为 `$30`），处理该模式的场景/演出逻辑。

模式跳转线索（静态）：`$C904` 读 Start 边沿，对 `$30` 为 `$1B/$1C/$1E/$19/$28` 有特殊处理；`$C6D2`（Start）进入战斗初始化，随后置 `$0500/$0510/$0520` 倒计时并循环 `$C681`（战斗主循环，调用 `$E9BC` 实体更新）。

## 7. 实体系统

16 个实体槽（X = 0..15），并行数组（每数组间隔 `$20`）：

| 地址 | 含义（静态推断） |
| --- | --- |
| `$0300,X` | 实体标志/类型，bit7 = 激活 |
| `$0320,X` | 坐标（y 相关） |
| `$0360,X` / `$0380,X` | 世界 X 低/高字节（16 位） |
| `$03E0,X` | 未知（参与剔除判断） |
| `$0560,X` | 标志位，bit4 参与可见性/更新判断 |

`$E9BC`（每帧，固定 bank 15）遍历 16 槽，按帧奇偶（`$95`）正/反向轮询；
`$E9FE` 是单实体更新前置：取世界 X 与参考坐标 `$F9:$FC` 求差，绝对值 ≥ `$68` 时走 `$EC33`（剔除/休眠）。

## 8. Bank 角色（静态初判）

| bank | 角色 | 依据 |
| --- | --- | --- |
| 0 | 模式级场景/演出逻辑 | `$8000` 按 `$30` 查 42 项表分派；含大量 FSM |
| 4 | 标题/演示/菜单与场景初始化 | 启动任务大量 `JSR $8000/$89C0/$8900/$8A40…` |
| 6 | 脚本虚拟机 | `$8023` 从栈上返回地址读指针表 `JMP ($00C1)`；`$8006` 8×8 乘法；`$803A` 间接取数 |
| 8 | 关卡/角色数据装载与 FSM | `$8000` 按 `$67` 从 `$81FE-$8294` 并行表装载；`$89F2`、`$9745` 各 15 项分派表 |
| 9 | 数据/辅助（`$8000` 与 `$A000` 双窗口都出现） | 表 `$A035/$A0B5`、`$A1xx` |
| 10 | 纯数据（曲线/表） | 无代码入口，`$9C00` 单点被调用 |
| 12 | 对象/精灵槽更新 | `$8000` 处理 `$0300` 数组、按 `$0320` 分档 |
| 14 | 引擎 + 全模式逻辑（固定） | `$C000-$DFFF`，模式处理 `$CA20-$DE5E` |
| 15 | 引擎核心（固定） | 向量、任务系统、实体更新、PPU/NMI 辅助、音效 |

## 9. 已知数据表

- 模式分派表：`$C9CA`（lo）/ `$C9F5`（hi），43 项
- 模式二级分派：bank 0 `$8011`（lo）/ `$803B`（hi），42 项
- bank 4 子分派：`$8DC8/$8DCB`（3 项）、`$9D56/$9D59`（3 项）
- bank 8 分派：`$8A0E/$8A1D`（15 项）、`$9761/$9770`（15 项）
- bank 12 分派：`$87B0/$87B3`（3 项）
- 标题文字："FINAL FIGHT" 等字符串在 `$C8DA` 起，`$C8B4` 拷贝到 `$0610/$0630` 名称表缓冲
- bank 8 关卡参数表：`$81FE-$8294`（按 `$67` 索引）

## 10. 动态阶段要确认的清单

1. `$30` 的模式编号含义（标题/选人/战斗/过场/结算）
2. `$F9:$FC` 到底是相机还是玩家坐标（`$E9FE` 的距离判断对象）
3. `$0300` 各字节的完整实体结构（尺寸、朝向、HP、动画）→ 决定敌人 AI 对接
4. 玩家攻击判定：招式表、伤害值、判定帧（结合 `$14/$16` 消费点 + 实体数组写入断点）
5. 各 bank 在战斗中实际被载入的时机（用于确认 bank 角色表）
6. 音效触发（`$F34A/$F34C` 一族）的通道分配

## 11. 复现命令

```bash
cd tools/re
python mff_static.py   # 仅固定 bank 的简单反汇编
python mff_banked.py   # 带 bank 上下文的完整追踪，产出 out/bank**.asm
```

> 清单中的 banked 地址是"名义基址"（$8000 或 $A000）下的 CPU 地址；同一 bank 若在两个窗口都被载入，地址表示可能重叠，但 bank 内偏移一致。

### 12.5 Boss 实测：Thrasher（第一关，类型 7）

推进方式：`CHEAT=1` 按 `$F928/$F92F` 打 ROM 补丁（玩家不扣血、不击倒）+ 非 Boss 敌人 HP 压到 1 + 脚本自动走位出拳；Boss 出现后不再压 HP。

出现流程：进入 Boss 区 → 模式 `$20`（演出）→ **模式 `$0A`（对话，等待按键，按 A 推进）** → 模式 0 正常战斗。Boss 登场台词："HEH-HEH. I AM THRASHER."

| 项 | 数值 |
| --- | --- |
| 类型 / HP | 7 / 72（`$0490+12`） |
| 接近（状态 `81`） | ≈0.68 px/帧（41 px/s），朝玩家走 |
| 冲撞（状态 `86`） | 117 帧，1.86 px/帧（112 px/s），横穿整个屏幕（x 498→280） |
| 跳跃攻击（状态 `85`） | 94 帧；屏幕 Y 133→76→130，跳高 ≈57 px |
| 近身抓取（`83` 7 帧 → `82` 63 帧循环） | 攻击 ID 31 |
| 攻击 ID | 冲撞/跳跃 = 22 → 伤害 `$FD16[22]=18`；抓取 = 31 → 伤害 `$FD16[31]=5` |

观测到的决策距离：`|dx| > 60` 用冲撞；中距离起跳；`|dx| ≤ 40` 抓取。
（无敌补丁下抓取会让 Boss 卡在 `82` 循环——正常游戏里玩家会掉血/被摔，所以循环会结束。）

### 12.10 命中时序与判定距离（观测）

### 12.16 自动跑批的可靠性与限制

- `FAST=1` 关闭逐指令覆盖率统计，速度约提升 1.5-2 倍（约 140 帧/秒）

- 已实测推进：第 1 关 Slum（Boss 7）→ 第 2 关 Riverside（Boss 8）→ 第 3 关（Boss 9）→ 第 4 关 Fujiyama 场景
- **savestate 断点续跑已实现**：`SAVE_EVERY=N` 定期写 `out/states/state_<帧>.json`（jsnes `toJSON`），`LOAD_STATE=... START_FRAME=...` 读档续跑；已验证读档后帧 2000 的状态与原始运行完全一致（注意 `fromJSON` 会重建 CPU，钩子需重新安装，脚本已处理）
- **仍会卡住**：部分门口的波次触发依赖特定条件（例如场上只剩类型 0 的事件物时场景不推进），玩家位置被关卡夹住，瞬移会被游戏逻辑覆盖回原值。断点探查证实：按 A/Start/上下、清类型 0、强推镜头都无法让该门口触发正常波次；**强推镜头能翻到下一段街区，但会跳过脚本触发器（Boss 不刷新）**。需要静态读 bank 6 的脚本/波次表，或人工在该处操作一次取得干净断点
- 已知 Boss 记录仅 5 条（id19-23 → 类型 7/8/9/8变体/11），第 4-6 关 Boss 大概率复用这些记录，但具体映射待补

### 12.18 玩家连段与位移机制（实测）

- 写日志确认：唯一一次命中（104→101，3 点伤害）由 **bank12 `$86EC`**（普通攻击扣血例程）写入；而武器攻击 ID 31 在玩家 L0 伤害表中对应 1 点——说明这次命中很可能是同时发生的普通攻击，武器投掷本身未命中（投掷物弹道不在实体槽数组里，可能是独立效果）
- 待补：投掷物的真实伤害与判定

**静态补充（武器攻击分支）**：
- 拾取后调用 `$89E3`（按角色/武器查表设置持械动画，表 `$8ACE/$8AD4/$8AD9/$8ADE/$8AE8` 等）与 `$8C00`
- `$8C00`：若 `$B2` 为负 → 设 `$30 = 2`、`$37 = 12`、调用 `$F2BE`；另一路径设 `$30 = $29`
- 说明武器攻击走的是**模式驱动**（`$30 = 2 / $29`）而不是玩家攻击 ID 表分支；之前扫描到的 `CMP #$1F` 实为模式比较（`LDA $30`），不是武器 ID
- 剩余：追模式 `2/$29` 的处理函数即可拿到投掷物生成、伤害与判定帧

**关卡结算**：Boss 死后是 "ROUND N CLEAR" 画面，EXP 按关卡重置（HUD 分母变化，如 033→054→090）；没有独立的油桶奖励画面。
