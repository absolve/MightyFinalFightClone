# Mighty Final Fight Clone - 项目现状

> 本项目是 NES 游戏《快打旋风》(Mighty Final Fight, Capcom 1993) 的 Godot 复刻版。
> 本文档记录当前代码库的实际实现情况，基于对 `MightyFinalFight/` 目录下所有脚本与场景的逐文件审查。

## 工程信息

- 引擎：Godot 4.6（`config_version=5`）
- 主场景：`res://scene/welcome.tscn`（标题画面）
- 分辨率：640×480（viewport 拉伸模式）
- 物理层：`player` / `playerHitBox` / `enemy` / `enemyHitBox`
- 全局 Autoload：`Game`（`res://autoload/game.gd`）
- 输入按键：WASD 移动、J 出拳、K 跳跃、Enter 开始（仅 P1 配置）

## 已实现内容（按模块）

### 1. 全局单例 `Game`（autoload/game.gd）
仅定义了枚举，无任何运行时逻辑：
- `playerState`：idle / walk / attack / hurt / hit_flying / jump / skill
- `direction`：up / down / left / right
- `PlayId`：p1 / p2 / p3 / p4（支持 4 人，但仅 p1 配置了按键）
- `gameObjType`：空枚举（待填充）

### 2. 标题画面（welcome）
- `welcome.tscn`：显示 Logo + "PUSH START" 文字 + "capcom co., ltd. 1993" 版权字样，黑底。
- `welcome.gd`：监听 `start` 按键但 `pass`，**未跳转到任何场景**。

### 3. 状态机框架（已搭建，未串联）
- `state.gd`：基类，定义 `enter/exit/update/physics_update/handle_input` 空实现。
- `stateMachine.gd`：持有 `currState`，每帧调用其 `update` / `physics_update` / `handle_input`。
- `playerState.tscn`：空的 state 节点。
- `stateMachine.tscn`：stateMachine 节点。
- **现状**：状态机可运行 `initialState` 的 `physics_update`，但**无任何状态切换逻辑**（没有 transition），只能算框架。

### 4. 战斗对象基类 `object`（object.gd / object.tscn）
- 继承 `CharacterBody2D`。
- 字段：`hp`、`invincible`、`state`、`zPos`、`speed=300`、`gravity=980`、`level`、`attack`、`vec`、`inAir`、`zVec`、`keyMapPrefix='p1'`、`playerId`。
- 节点引用：`$body`（含 AnimatedSprite2D `ani`、`hurtBox` Area2D、`hitBox` Area2D）、`$player`（AnimationPlayer）、`$tree`（AnimationTree）、`CollisionShape2D`。
- `_ready`：仅根据 `playerId` 设置 `keyMapPrefix`，**无移动、无动画、无碰撞处理**。

### 5. 玩家状态（playerState.gd，唯一含实际逻辑的状态）
- 继承 `state.gd`，`_ready` 中 `await owner.ready` 后取 `player=owner`。
- `physics_update` 实现：
  - 读取 WASD 输入轴，设置 `player.vec`（速度 300）。
  - 跳跃：按 K 时若 `!inAir` 则 `zVec=-500`；空中施加重力 `zVec += gravity*delta`，更新 `bodyNode.position.y`，落地归零。
  - `player.set_velocity(vec)` + `move_and_slide()`。
- **缺失**：无动画调用、无攻击处理（J 键未用）、无状态切换、未区分 idle/walk、`print(player.zVec)` 调试残留。

### 6. 玩家角色场景
三个可玩角色均已建场景与贴图，但脚本几乎为空：

| 角色 | 脚本 | 场景动画 |
|------|------|----------|
| Cody | `cody.gd`（空 `extends object`） | act1-5 / default / down / fall / grap / hurt / jump / squat / throw / wake / walk（贴图帧完整） |
| Guy  | `guy.gd`（空 `extends object`） | 同样配置了多组 SpriteFrames 动画 |
| Haggar | （无独立脚本，直接用 object） | SpriteFrames 定义了多个动画但多数帧为空 |

`cody.tscn` 结构最完整：含 hurtBox / hitBox（Area2D，**shape 为空 RectangleShape2D，未设置尺寸**）、AnimationPlayer（idle/walk 动画轨道为空）、AnimationTree（空状态机）、playerState 子节点。

### 7. 地图与关卡（map / stage）
- `map.gd`：Node2D，仅声明 `bgMusic`、`nextStage` 变量，`_ready` 为空。
- `stage1.gd`：`extends map`，空。
- `stage1.tscn`：实例化 map，背景贴图为 `Round 1.png`（缩放 3 倍）。
- `stageManage.gd/tscn`：空 Node2D，**关卡管理器无任何逻辑**。
- **现状**：无滚动、无摄像机跟随、无敌人波次、无关卡切换。

### 8. 背景（bg.gd / bg.tscn）
Node2D + AnimatedSprite2D + Sprite2D，脚本为空。

### 9. 道具（item.gd / item.tscn）
Area2D + CollisionShape2D + AnimatedSprite2D，仅声明 `type` 变量，`_ready` 为空。**无拾取逻辑、无与玩家交互**。

### 10. 资源储备
- **美术**：Cody/Guy/Haggar 全套动作帧、Enemies、Bosses、Items & NPCs、HUD、Cutscenes、Round 1 背景，已切图且导入。
- **音效**：22 个音效文件（出拳、击中、起跳、落地、旋风腿、甩人、玩家死光、玩家被击飞、敌人倒地、发出光波、双脚跳踢、连环腿1/2、野人脚步、集聚光波、飞扑、选人、dada、shoot、dragon_fist 等），均已导入但**无音频管理器、无播放调用**。
- **字体**：PressStart2P（像素字体），用于标题画面。

## 总体评估

| 维度 | 完成度 | 说明 |
|------|--------|------|
| 工程框架 | 60% | project.godot 配置、按键、物理层、autoload 已就位 |
| 状态机 | 30% | 框架可跑，无切换、无具体子状态 |
| 玩家移动 | 40% | 平面移动 + 跳跃/Z 轴重力有雏形，缺动画与状态联动 |
| 战斗系统 | 0%  | hitBox/hurtBox 结构存在但 shape 为空，无碰撞、无伤害 |
| 敌人系统 | 0%  | 无敌人脚本，无 AI，无生成 |
| 关卡系统 | 10% | 仅 Round 1 背景静态显示 |
| HUD | 0%  | 无血条、无计分、无任何 UI |
| 音频 | 0%  | 资源就绪，无播放系统 |
| 道具 | 0%  | 结构在，逻辑空 |
| 选人/菜单 | 0%  | 标题画面未跳转 |

**结论**：项目处于**早期脚手架阶段**。框架性代码（状态机、对象基类、角色场景与动画帧）已搭好，但所有核心玩法（战斗、敌人、关卡推进、HUD、音效）均未实现。下一步应优先打通「移动→动画→攻击→命中」的最小可玩闭环。
