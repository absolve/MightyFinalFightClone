# Mighty Final Fight Clone - 项目现状

> 本项目是 NES 游戏《快打旋风》(Mighty Final Fight, Capcom 1993) 的 Godot 复刻版。
> 本文档记录当前代码库的实际实现情况，基于对 `MightyFinalFight/` 目录下所有脚本与场景的逐文件审查。

## 工程信息

- 引擎：Godot 4.7.2（`config_version=5`，project.godot `config/features` 为 "4.7"）
- 主场景：`res://scene/welcome.tscn`（标题画面）
- 分辨率：640×480（viewport 拉伸模式）
- 物理层：`player` / `playerHitBox` / `enemy` / `enemyHitBox`（原 `playerHItBox`/`enemyHItBox` 拼写已修正）
- 全局 Autoload：`Game`（`res://autoload/game.gd`）、`InputRecorder`（`res://autoload/input_recorder.gd`）
- 输入按键：P1 = WASD 移动 + J 出拳 + K 跳跃；P2 = 方向键移动 + Z 出拳 + X 跳跃；Enter 开始
- 命令行验证：`Godot_v4.7.2-stable_mono_win64_console.exe --headless --path MightyFinalFight <场景>`

## 已实现内容（按模块）

### 1. 全局单例
- `Game`（autoload/game.gd）：仅定义枚举，无任何运行时逻辑。
  - `PlayerState`：IDLE / WALK / ATTACK / HURT / HIT_FLYING / JUMP / SKILL
  - `Direction`：UP / DOWN / LEFT / RIGHT
  - `PlayId`：P1 / P2 / P3 / P4（P1/P2 已配置按键）
  - `GameObjType`：空枚举（待填充）
- `InputRecorder`（autoload/input_recorder.gd）：输入缓冲单例，按 playerId 分桶，
  时间戳衰减（bufferWindow=0.5s，pop_front 剔除最旧项），提供 record/getBuffer/clearBuffer。

### 2. 标题画面（welcome）
- `welcome.tscn`：显示 Logo + "PUSH START" 文字 + "capcom co., ltd. 1993" 版权字样，黑底。
- `welcome.gd`：按 `start`（Enter）→ `change_scene_to_file` 进入 stage1（选人画面未做，暂直连）。

### 3. 状态机框架（玩家与敌人共用）
- `state.gd`：基类（class_name `State`），缓存 `obj`（所属 FightObject）/`stateMachineNode`，
  定义 `enter/exit/update/physics_update/handle_input/onAnimationFinished` 虚实现；
  `_ready` 中连接 `obj.tree.animation_finished`（带片段名参数，驱动连段等动画事件）。
- `stateMachine.gd`：驱动器（class_name `StateMachine`），持有 `currState`，
  实现 `transition_to(statePath, data)`（**允许自转移**，供连段递进），
  每帧分发 update/physics_update/handle_input，**不含任何角色专属逻辑**。
  `_ready` 在 `await owner.ready` 后还要等 `STARTUP_DELAY_FRAMES`（2）个物理帧才进入初始状态：
  AnimationTree 刚进树时尚未就绪，此时发出的首个 `playback.start()` 会被丢弃，
  角色会一直停在场景里的初始贴图不动（已定位修复，见 §4.6）；
  三个分发回调都对 `currState` 判空。
- `player_state.gd`：玩家状态基类（class_name `PlayerState`），提供共享的
  `tryPunchCombo()`（出拳统一入口：**按住方向时一律普通攻击**，原地出拳才查搓招表 →
  下+拳进蹲击 → 否则进 attackState）与 `tryJump()`；敌人状态直接继承 State。
- 玩家状态在 `script/states/`：`idle_state` / `walk_state` / `jump_state` /
  `attack_state` / `skill_state` / `hurt_state`（均注册全局类名）。
- 旧的 `playerState.gd` / `playerState.tscn` 已删除。

### 4. 战斗对象基类 `FightObject`（object.gd / object.tscn）
- 继承 `CharacterBody2D`，class_name `FightObject`，玩家与敌人的共同基类。
- 导出字段：`hp`/`maxHp`/`attack`/`speed`/`jumpSpeed`/`gravity`/`playerId`/
  `combos: Array[ComboDef]`（挂招式 .tres）/`skillAnims`（必杀名→动画名）；
  基本操作相关：`depthSpeedFactor`（上下方向速度系数 0.6）、`airControlFactor`（空中控制 0.7）、
  `playBounds: Rect2`（可活动范围，size 为零表示不限制，由关卡 `Map` 开场写入）。
- 普通字段：`faceDir`（朝向，控 flip_h 与 hitBox 偏移）、`vec`、`inAir`、`zVec`、
  `invincible`、`keyMapPrefix`（由 playerId 派生 `p1`~`p4`）。
- **基本操作能力**（各状态共用，避免重复实现）：
  `getMoveInput()`（四向原始轴值）/ `velocityFromInput(dir, control)`
  （上下乘纵深系数）/ `faceInput()`（按输入转向）/
  `moveByInput(control)`（读输入→设速度→move_and_slide→钳进 playBounds）/
  `moveSelf()` / `clampToBounds()` / `startJump()` / `applyGravity(delta)`（返回是否刚落地）。
- 动画/命中：`playAnim`（重复播放保护，经 playback.start 切换）/
  `hasAnim` / `getAnimLength`（供连段算可取消时刻）/ `setHitBoxEnabled` /
  `takeDamage(amount, fromDir)`（扣血→生成伤害飘字 [DamageNumber]→进 hurtState 并带击退方向）/
  `onHitBoxAreaEntered`（hitBox 命中→`target.takeDamage(attack, faceDir)`）/
  `buildAnimations` + 虚函数 `getMoveOverrides`（子类提供动画覆盖表）。
- **攻击框翻转修复**：`cody.tscn` 把攻击框的横向偏移写在 `hitBox/shape`
  （CollisionShape2D position.x=30）而不是 `hitBox` 节点上，旧代码取
  `hitBoxNode.position.x`（=0）当基准，导致**朝左时攻击框仍留在右侧**。
  现由 `setupHitBoxOffset()` 自动识别偏移写在 Area2D 还是其碰撞形状子节点上，`setFaceDir` 翻转实际承载偏移的节点。
- 节点引用：`$body`（含 AnimatedSprite2D `ani`、`hurtBox`、`hitBox`）、`$stateMachine`、
  `$player`（AnimationPlayer）、`$tree`（AnimationTree）；
  `playback`（AnimationNodeStateMachinePlayback）在 buildAnimations 后缓存。

### 4.6 动画系统（anim_builder.gd，class_name `AnimBuilder`）
- 把角色 SpriteFrames 的每个动画转成 AnimationPlayer 片段
  （`body/ani:animation` / `body/ani:frame` 离散值轨道），
  并生成 AnimationNodeStateMachine（一动画一状态，**代码 start() 切换、无需连线**）。
- 带 `hitWindow` 的片段额外生成**方法轨道**，到点调用 `setHitBoxEnabled` 开关攻击框，
  为受伤框/攻击框逐帧判定打底（后续可同样扩展 hurtBox 窗口）。
- 覆盖表由角色脚本提供（如 Cody 的 `MOVE_OVERRIDES`）：fps / loop / hitWindow。
- **产物落盘可编辑器验证**：`data/anims/<角色>_library.tres`（动画库）与
  `<角色>_state_machine.tres`（状态机）由编辑器工具
  `script/editor/anim_build_tool.gd` 生成——打开角色场景后运行该脚本即重生成并挂到
  player/tree 节点（场景标记未保存，Ctrl+S 生效）。编辑器里可直接打开片段时间轴
  （含命中窗口方法键）与状态机面板查看微调；改动覆盖表数值后重跑工具即可刷新。
- 运行时 `FightObject.buildAnimations`：场景已配置状态机则直接取用；
  未配置（敌人初建、guy/haggar 尚未接线、sprite_frames 为空）则运行时兜底构建或跳过。
- 注意：Godot 4.6/4.7 中 AnimationNodeStateMachinePlayback 的切换方法是
  `start(node, reset)` / `travel(to_node)`，**没有 play()**。
- 注意：场景里的状态机**没有连线**（一动画一状态、全靠代码 `start()` 切换），
  所以 `travel()` 用不了，只能用 `start()`；而 `start()` 有 2~3 帧延迟才生效，
  在 AnimationTree 就绪前发出的调用会被直接丢弃。因此 `StateMachine` 推迟 2 帧再进入
  初始状态（见 §3），否则角色会一直是场景里的初始贴图、连走路都不换帧。

### 4.7 逐帧判定框（hitbox / hurtbox）
- 引入第三方插件 **goutte.animated_shape_2d**（MIT，v1.5.0），放在
  `addons/goutte.animated_shape_2d/`，已在 `project.godot` 的 `[editor_plugins]` 启用。
  已在 Godot 4.7.2 下验证：编辑器加载零报错，底部多出 “Animated Shape” 面板。
- 插件作用：按 `AnimatedSprite2D` 的**每个动画的每一帧**，把目标 `CollisionShape2D`
  的形状/位置/禁用状态换掉，用来做逐帧变化的 hurtbox / hitbox。
  数据放在 `ShapeFrames2D` 资源里（每条是 `ShapeFrame2D`：shape + position + disabled）。
- 本项目的接线：
  - `object.tscn` 根节点下新增 `hurtShape`、`hitShape` 两个 `AnimatedShape2D`
    （`animated_sprite` 指向 `body/ani`）；
  - `collision_shape` 指向 `body/hurtBox/shape` / `body/hitBox/shape`，
    这两个 CollisionShape2D 只存在于角色场景（cody.tscn），所以引用在角色场景里覆盖；
  - 形状库 `data/shapes/cody_hurt_shapes.tres` / `cody_hit_shapes.tres`，
    由角色场景覆盖到对应节点的 `shape_frames` 上。
- 当前只定了 **hurtbox 的 idle（SpriteFrames 里的 `default`）一帧**：26×40、位置 (0,-2)，
  与原 CollisionShape2D 一致，手感零变化。其余动画未定义，走
  `use_initial_as_fallback`（回退到 CollisionShape2D 初始形状）。
- hitbox 的 `ShapeFrames2D` 目前是空的，且设了
  `use_initial_as_fallback=false` + `use_previous_as_fallback=true`：
  没有帧数据时插件**完全不碰** CollisionShape2D。
  原因：攻击框的横向偏移由 `FightObject.setFaceDir()` 靠改 `position.x` 翻转，
  若插件也去写 position，两套逻辑会互相覆盖。
  后续若要让插件接管 hitbox，需先决定「翻转」由谁负责（插件的 `handle_flip_h`
  是翻转父 Area2D 的 scale，与现有做法不同）。
- `handle_flip_h` 一律关闭：翻向由本项目自己的 `setFaceDir()` 统一处理。
- 编辑器里用法：选中 `hurtShape`/`hitShape` 节点 → 底部 “Animated Shape” 面板 →
  选动画与帧 → 新建/编辑该帧的形状。
- 踩坑记录：`.tscn` 里给节点写 `animated_sprite = NodePath(...)` 这类**节点引用**时，
  必须同时在该节点行加上 `node_paths=PackedStringArray("animated_sprite", ...)`，
  否则 Godot 不会把 NodePath 转成节点引用，属性恒为 null；
  路径是相对**该节点自身**的（指向同级的 body/ani 要写 `../body/ani`）。

### 4.5 玩家基类 `Player`（player.gd）
- 继承 FightObject，Cody/Guy/Haggar 继承本类；**敌人直接继承 object.gd**。
- 在 `_input` 阶段把本玩家输入写入 InputRecorder（`_input` 整树先于
  `_unhandled_input`，保证录入早于状态机派发，与节点位置无关）。

### 5. 玩家状态（script/states/*.gd）
- `IdleState`：静止播放 default；有输入转 walkState；监听跳跃与出拳。
  若因空中受击硬直结束等原因仍浮空，本状态负责继续受重力、落回地面后才恢复操作
  （否则会出现「悬空待机」）。
- `WalkState`：四向移动，**上下方向乘 `depthSpeedFactor`（0.6）**，即纵深移动比横向慢；
  移动结果被 `playBounds` 钳制在关卡可活动范围内；播放 walk，贴图按朝向翻转。
- `JumpState`：起跳 `startJump()`（zVec=-jumpSpeed），空中按 `airControlFactor` 修正方向并受重力；
  **上升播放 jump、越过顶点后切 fall**；落地回 idleState。
  空中每跳可出一次攻击：拳= `jumpAttack`，按住下+拳= `jumpKick`（素材缺失时退回 jumpAttack），
  攻击播放期间锁朝向，动画结束回到当前飞行片段（jump/fall）。
- `AttackState`：act1→act2→act3 三段连击，**可取消窗口**（`CANCEL_RATIO`=0.55 × 片段长度）：
  出招期间按下的拳先置 `buffered`，动画进度超过窗口就立刻接下一段，不必等整段播完；
  片段过短时 `onAnimationFinished` 兜底再判一次。**进入时清空输入缓冲**（否则发起攻击的那一拳会让
  act1 自动连段）；起手按当前方向转向；下+拳为蹲击（squatAttack，单段不连段，
  素材缺失时退回 act1）；攻击框由动画方法轨道按命中窗口开启。
- `SkillState`：按 `skillAnims` 映射播放必杀动画（攻击框同样走方法轨道），结束回 idleState；
  映射到的片段缺失时退回 act4。
- `HurtState`：受击 0.4s 硬直 + 短暂无敌，**沿出手方向击退**（初速 220、衰减 1400）并转身面向出手者，
  空中被打时同样受重力，结束回 idleState。
- **走打与搓招的区分**（`PlayerState.tryPunchCombo`）：按住任意方向键出拳一律算普通攻击，
  只有**原地**（不按方向）出拳才查搓招表。否则「边走边打」会被 skill1（方向+拳）截走，
  普通拳就再也打不出来；要放必杀得先松开方向、再原地出拳。
