## 1. 搓招 / 按键连招系统（核心机制）

### 1.1 功能说明

「搓招」指玩家通过特定方向键 + 攻击键的时序组合触发必杀技，是清版动作游戏的核心手感来源。
> 注意：本作（NES 版）原作**并没有街霸式搓招**。原作特殊技输入为「B → 前」的时机型指令，
> 不是方向键序列；Cody/Haggar 需 LV4，Guy 日版说明书为 LV1（英文攻略多写 LV4）。
> 特殊技包括 Cody「Tornado Sweep / Rising Uppercut」、Guy「Sonic Kick（英：Tornado Kick）/ Fire Kick」、
> Haggar「Scramble Haggar Press（英：Running Clothesline）」；另有 A+B 旋转必殺技（消耗自身体力）。
> 原作的普通连击是**命中驱动**的 4 段连击（第 4 段高伤击倒，第 3 段后可投技），不是按输入固定递进。
> 本项目搓招系统是**扩展玩法**（沿用既有 godot3 demo 设计），不是对原作的还原；连击则按原作命中驱动实现。
> 详见 [原作资料.md](原作资料.md) §3.2-3.8。

示例（沿用既有 godot3 demo 的设计）：
- `→ + 拳` → skill1
- `→ ← + 拳` → skill2
- `↑ ↓ + 拳` → skill3

### 1.2 既有实现回顾（godot3，`F:\godotTestDemo\godot3inputCombo`）

| 文件 | 职责 |
|------|------|
| `autoload/game.gd` | 硬编码 `combos` 数组：`{name, combos:[[序,序],...], priority}` |
| `script/player.gd` | 维护 `inputList` 环形缓冲（max 50）；`checkCombo()` 用字符串子串匹配；`aniFinish()` 动画结束回调驱动连段 |
| `script/main.gd` | 独立维护一份 inputList（max 7）仅用于 UI 显示 |
| `scene/player.tscn` | AnimationTree + AnimationNodeStateMachine，idle/move/punch1-3/skill1-3 状态与转移 |

**核心匹配逻辑**（`player.gd::checkCombo`）：
```gdscript
var temp = "".join(inputList)              # 拼成 "leftpunchright"
for i in combo:
    var str1 = "".join(y)                   # "leftpunch"
    if temp.find_last(str1) != -1:          # 子串命中
        existCombo.append(i)
existCombo.sort_custom(self, "sortCombo")   # 按 priority 降序
animation_state.travel(existCombo[0].name)
```

**缓冲衰减**：
```gdscript
timer += 1
if timer > timeDelay:      # timeDelay=30 帧 ≈ 0.5s
    timer = 0
    inputList.pop_back()   # ⚠ 弹出的是最新一项
```

### 1.3 既有实现的问题

1. **衰减方向错误**：`add2InputList` 用 `push_back` 追加，而衰减用 `pop_back()` 移除最新项——应为 `pop_front()` 移除最旧项，否则玩家最新的有效输入会被先丢弃。
2. **字符串子串匹配有歧义**：`"leftpunch"` 会命中 `"left"` + 任意 + `"punch"` 的任意间隔组合，无法保证时序相邻；`"down"` 与 `"punch"` 拼接后也可能误匹配 `"downpunch"` 子串。
3. **无时间窗口约束**：只按帧数粗略衰减，没有「单次搓招必须在 X 毫秒内完成」的判定，慢速连点也能凑出必杀。
4. **连招定义硬编码在 autoload**：加新招要改 `game.gd`，无法数据驱动，不符合扩展偏好。
5. **输入缓冲重复**：`player.gd` 与 `main.gd` 各存一份 inputList，状态不同步。
6. **无多玩家支持**：单 buffer，P2 无法复用。
7. **`existCombo[0].name` 未校验非空**：极端情况下 `existCombo` 排序后仍可能取到错。

### 1.4 改进方案（Godot 4，推荐用于本项目）

设计目标：**解耦、数据驱动、时间戳衰减、严格时序匹配、多玩家就绪**。

#### 架构分层

```
InputRecorder (autoload)     ─ 单例，按 playerId 维护输入缓冲，时间戳衰减
        ↓ signal: input_recorded(player_id, action)
ComboDef (Resource)          ─ .tres 文件，定义单招：name/inputs/priority/window
ComboMatcher (autoload/类)    ─ 取 buffer + combo 列表，返回最佳匹配
player 的 attack/idle state   ─ 订阅信号，命中则 transition_to(skill_state)
```

#### (A) InputRecorder —— 输入缓冲单例

改进点：用时间戳而非帧计数；过期自动剔除；每玩家独立。

```gdscript
# autoload/input_recorder.gd
extends Node
class_name InputRecorder

# 每条输入：动作名 + 记录时刻（秒）
class InputEntry:
    var action: String
    var time: float
    func _init(a: String, t: float) -> void:
        action = a; time = t

# buffer_window：单条输入最长保留时间（秒），超过自动剔除
@export var buffer_window: float = 0.5
# 每玩家的缓冲
var _buffers: Dictionary = {}   # playerId -> Array[InputEntry]

func record(player_id: int, action: String) -> void:
    if not _buffers.has(player_id):
        _buffers[player_id] = []
    _buffers[player_id].append(InputEntry.new(action, Time.get_ticks_msec() / 1000.0))
    input_recorded.emit(player_id, action)

# 取某玩家当前有效缓冲（已剔除过期项），返回动作名数组
func get_buffer(player_id: int) -> Array[String]:
    var arr: Array[String] = []
    if not _buffers.has(player_id):
        return arr
    var now: float = Time.get_ticks_msec() / 1000.0
    var buf: Array = _buffers[player_id]
    # 移除过期（从头部，最旧）
    while buf.size() > 0 and now - buf[0].time > buffer_window:
        buf.pop_front()
    for e in buf:
        arr.append(e.action)
    return arr

func clear(player_id: int) -> void:
    if _buffers.has(player_id):
        _buffers[player_id].clear()

signal input_recorded(player_id: int, action: String)
```

> 关键差异：`pop_front()` 移除最旧项（修正 godot3 的方向错误）；按真实时间而非帧数，帧率波动下行为一致。

#### (B) ComboDef —— 数据驱动招式定义

```gdscript
# script/combo_def.gd
extends Resource
class_name ComboDef

@export var name: StringName        # 必杀名，对应 AnimationTree 状态
@export var inputs: Array[StringName] = []  # 时序输入，如 ["right","left","punch"]
@export var priority: int = 0       # 数字大优先
@export var time_window: float = 0.4 # 该招必须在 0.4s 内完成
@export var damage: int = 10
@export var cost_hp: int = 0        # 消耗自身血量（原作必杀扣血）

# 供编辑器创建 .tres：res://data/combos/cody_skill1.tres 等
```

招式表改用 `res://data/combos/<char>/*.tres`，加新招只加资源文件、零代码改动（呼应数据驱动偏好）。

#### (C) ComboMatcher —— 严格时序匹配

改进点：做**后缀严格匹配**——只有缓冲末尾 N 项与招式输入序列完全一致才算命中，避免子串歧义。

```gdscript
# script/combo_matcher.gd
class_name ComboMatcher

# combos: Array[ComboDef]  buffer: Array[String]
static func match(combos: Array, buffer: Array[String]) -> ComboDef:
    var best: ComboDef = null
    for def in combos:
        var seq: Array = def.inputs
        if seq.size() == 0 or seq.size() > buffer.size():
            continue
        # 取缓冲末尾 len(seq) 项做严格比较
        var start: int = buffer.size() - seq.size()
        var ok: bool = true
        for i in seq.size():
            if buffer[start + i] != seq[i]:
                ok = false
                break
        if ok:
            # 优先取更长的招式（输入更多更难搓），同长度取 priority 高的
            if best == null or seq.size() > best.inputs.size() \
               or (seq.size() == best.inputs.size() and def.priority > best.priority):
                best = def
    return best   # 可能为 null
```

> 关键差异：严格后缀匹配替代 `find_last` 子串，杜绝误判；长序列优先（避免 `→拳` 抢掉 `→←拳`）。

#### (D) 玩家侧集成（接入状态机）

```gdscript
# script/states/idle_state.gd （节选）
extends "res://script/state.gd"

func handle_input(_event: InputEvent) -> void:
    var p = player
    if Input.is_action_just_pressed("%s_punch" % p.keyMapPrefix):
        InputRecorder.record(p.playerId, "punch")
        # 先查必杀
        var matched := ComboMatcher.match(p.combos, InputRecorder.get_buffer(p.playerId))
        if matched:
            state_machine.transition_to("skill", {skill = matched.name})
            InputRecorder.clear(p.playerId)
        else:
            state_machine.transition_to("attack", {hit = 1})
    # 方向键也录入缓冲（供搓招判定）
    for a in ["up","down","left","right"]:
        if Input.is_action_just_pressed("%s_%s" % [p.keyMapPrefix, a]):
            InputRecorder.record(p.playerId, a)
```

```gdscript
# script/states/attack_state.gd （节选，连段）
func enter(_prev, data) -> void:
    hit_count = data.get("hit", 1)
    player.ani.play("punch%d" % hit_count)

func on_animation_finished(anim_name) -> void:
    if not anim_name.begins_with("punch"):
        return
    var buf := InputRecorder.get_buffer(player.playerId)
    # 连段：缓冲末尾是 punch 且未到第 3 段
    if buf.size() > 0 and buf.back() == "punch" and hit_count < 3:
        InputRecorder.clear(player.playerId)
        state_machine.transition_to("attack", {hit = hit_count + 1})
    else:
        state_machine.transition_to("idle")
```

#### (E) AnimationTree 状态机

沿用既有 `player.tscn` 的 AnimationNodeStateMachine 结构（idle/move/punch1-3/skill1-3），通过 `state_machine.travel(name)` 驱动，无需改动。

### 1.5 与原实现的对照表

| 维度 | godot3 既有 | godot4 改进 |
|------|-------------|-------------|
| 衰减 | 帧计数 + `pop_back()`（方向错） | 时间戳 + `pop_front()`（最旧优先） |
| 匹配 | 字符串子串 `find_last` | 后缀严格逐项比较 |
| 歧义 | `→拳` 可能误命中 `→←拳` | 长序列优先 + 严格后缀，无歧义 |
| 招式定义 | 硬编码 autoload 数组 | `.tres` 资源文件，数据驱动 |
| 多玩家 | 单 buffer | 按 playerId 分桶 |
| 输入源 | player/main 各存一份 | InputRecorder 单一来源 + 信号广播 |
| 时间窗口 | 无 | ComboDef.time_window 可单招配置 |

## 2. 玩家移动与状态机

### 设计
- 沿用既有 `state.gd` / `stateMachine.gd` 框架，`transition_to(path, data)` 支持自转移（连段递进）。
- 状态：idle / walk / jump / attack(1-3 连段) / hurt / hit_fly / skill / grab / throw。
  已实现 idle / walk / jump / attack / skill / hurt，**未做 hit_fly / grab / throw**。
- 移动：平面四向（WASD），速度 `speed`=300；跳跃用 `zVec` + `gravity` 模拟伪 3D。
- 朝向 `faceDir` 控制贴图 `flip_h` 与 hitBox 偏移。
- **玩家需要哪些动画、每个动画用哪几帧贴图**，见 [玩家动画配置表.md](玩家动画配置表.md)：
  动画名是代码契约（`idle/walk/jump/fall/jumpRoll/jumpAttack/jumpKick/hurt/act1-3/squatAttack/act4/act5/act7`），
  fps / loop / 命中窗口在 `script/<角色>.gd` 的 `MOVE_OVERRIDES`，帧贴图在 `data/sprites/<角色>_frames.tres`。

### 已实现的基本操作规则（v2，2026-10 补完）

**移动**
- 输入用**原始轴值**（`Input.get_axis`）而非 `get_vector` 归一化：斜向 = (1,1)，方向感更硬朗。
- **纵深减速**：上下方向的位移乘 `depthSpeedFactor`（默认 0.6），即横向 300、纵向 180 ——
  清版动作游戏的标准手感，上下走不该和横向一样快。
- **可活动范围**：`FightObject.playBounds: Rect2`（世界坐标，size 为零=不限制），
  由关卡 `map.gd` 的 `applyPlayBounds()` 在 `_ready` 写给分组 `players` 里的所有玩家；
  每帧移动后 `clampToBounds()` 钳制 x/y，角色不会走出关卡地面带。
- 朝向：站立/行走/起跳都以「当前横向输入」决定 `faceDir`；攻击起手也会先按方向转向
  （按住左出拳 → 朝左打）。

**跳跃**
- `startJump()` 给 `zVec = -jumpSpeed`；`applyGravity(delta)` 统一推进 `body` 的 y 偏移，
  落地归零并返回 true，`inAir` 同步复位（这是**视觉上的伪 Z 轴**，碰撞体始终在地面）。
- **上升播 `jump`、越过顶点播 `fall`**（素材缺失时统一退回 `jump`），落地回 idle。
- 空中移动乘 `airControlFactor`（0.7）；起跳瞬间保留当前方向速度，跑动起跳不会立刻刹停。
- 空中每跳**可出一次**攻击：拳=`jumpAttack`，按住下+拳=`jumpKick`（素材缺失退回 jumpAttack）；
  攻击播放期间锁朝向，避免判定框中途翻面；动画结束回到当前飞行片段。
- 空中受击：hurt 状态同样受重力；硬直结束若仍浮空，由 idle 状态继续下落（不会悬空）。

**普通攻击**
- 三段连击 act1→act2→act3，**可取消窗口**：出招期间按下的拳先置 `buffered`，
  动画进度超过 `CANCEL_RATIO`(0.55)×片段长度 就立刻接下一段，不必等整段播完；
  片段过短时由动画结束回调兜底再判一次。第 3 段后不再连段。
- 进入攻击状态时清空 InputRecorder 缓冲，避免「发起攻击的那一拳」被当成连段输入。
- 下+拳 = 蹲击 `squatAttack`（单段、不连段；素材缺失退回 act1）。
- **走打与搓招分离**：按住任意方向键出拳一律是普通攻击；只有**原地**（不按方向）出拳
  才去查搓招表。原因：skill1 的输入就是「方向+拳」，若不隔离，边走边打永远被必杀截走，
  普通拳（以及三段连击）实际打不出来。要放必杀需先松开方向再原地出拳。

**受击**
- `takeDamage(amount, fromDir)`：`fromDir` 为出手者朝向 —— 受击者被推向该方向
  （初速 220、衰减 1400）、转身面向出手者、0.4s 硬直 + 短暂无敌，结束回 idle。
- 扣血同时生成伤害飘字（DamageNumber）。

### 实现要点（已落地）
- 通用能力集中在 `object.gd`（`getMoveInput` / `velocityFromInput` / `faceInput` /
  `moveByInput` / `clampToBounds` / `startJump` / `applyGravity` / `hasAnim` / `getAnimLength`），
  状态只做输入派发与动画切换，避免同一套移动逻辑在多个状态里复制。
- `object.gd` 增 `faceDir`、`maxHp`、`takeDamage()`、`invincible`。
- `playerState.gd` 拆成多个子状态文件，每个独立处理输入与动画。
- ⚠️ **启动帧陷阱**：AnimationTree 刚进树时未就绪，此时 `playback.start()` 会被丢弃，
  角色会停在场景里的初始贴图。`StateMachine` 因此延后 2 帧（`STARTUP_DELAY_FRAMES`）
  再进入初始状态；`playAnim` 另有 2~3 帧生效延迟，所以**不能**每帧重复调用 `start()`
  （会不断 reset，永远不生效）。
- 跳跃落地播放 `落地.wav`，起跳播放 `起跳.wav`（**待接音频系统**）。
- 回归测试见 `doc/项目现状.md` §13 与 `MightyFinalFight/test/player_ops_test`。

## 3. 战斗与命中判定

### 设计
- `object.tscn` 已有 hitBox / hurtBox（Area2D），补 CollisionShape2D 尺寸。
- layer/mask：hitBox(layer=playerHitBox, mask=enemy) ↔ enemy hurtBox(layer=enemy, mask=playerHitBox)。
- 命中流程：攻击动画关键帧启用 hitBox → `area_entered` → 调 `target.takeDamage(dmg, fromDir)` → 目标入 hurt/hit_fly 状态。
- 连段：attack 状态 1→2→3 段递进，第 3 段击飞（见 §1 攻击状态示例）。

### 实现要点
- AnimationPlayer 用 method track 在攻击帧调用 `enable_hitbox(true/false)`。
- 命中后短暂顿帧（`Engine.time_scale` 或暂停一帧）增强手感。

## 4. 敌人 AI

### 设计
- `enemy.gd extends object`，状态：idle/pursue/attack/hurt/dead。
- 追击：按玩家位置走 `move_and_slide`，进入攻击距离则 attack。
- 死亡：播放 `敌人倒地.wav` → 掉落概率生成 item → 移除节点。
- 数据驱动：`enemy_def.tres`（hp/attack/speed/ai_type）。

  要坐实需按 `$05B0` 类型 ID 逐帧比对。
- 远程兵不改状态脚本本身：`EnemyIdleState` 与 `EnemyChaseState` 的 `attackStatePath`
  在场景里指向 `throwState`，近战兵保持默认 `attackState`。
- 弹体分敌我两侧：`projectile_knife.tscn`（Cody 用，layer=playerHitBox / mask=enemy）与
  `projectile_knife_enemy.tscn`（El Gado 用，layer=enemyHitBox / mask=player）。
- **贴图待接，判定框已可用**：各场景都带 `hurtBox`（layer=enemy）与 `hitBox`（layer=enemyHitBox、
  mask=player）加形状，实测玩家能打掉敌人血。命中窗口正常由动画方法轨道打开
  （`getMoveOverrides()` 的 `hitWindow`，见 AnimBuilder）；`ani.sprite_frames` 还没挂时，
  [EnemyAttackState] 的 `fallbackHitWindow`（默认 0.05~0.2s，对应实测出手后第 3~8 帧命中）
  兜底开框，接上动画后自动失效。`EnemyThrowState` 把兜底窗口清零，伤害只由弹体结算。
- 48×48 的切条已在 `sprite/enemy/Enemies_*.png`。
- 已知缺口：类型 4 的对空上段（状态 `89`，dy 18~31）需要第二个判定框；
  类型 6 的举摔投技需要玩家受控状态配合。

## 5. 关卡推进

### 设计
- `map.gd` 管背景滚动：玩家接近屏幕右侧 → 滚动 bg + 摄像机。
- `stageManage.gd` 波次状态机：刷怪 → 清场检测 → 下一波 → Boss → 关卡结束 → `nextStage`。
- 波次配置：`data/stages/round1.json`（敌人类型/数量/坐标/触发条件）。

### 已落地：房间制关卡（2026-11）

一关拆成若干**房间**，玩家清空一间才前进下一间；关卡场景不一次性加载全部房间，
每次只实例化当前房间并预加载下一间。

数据（全部 `.tres`，Inspector 可编辑，遵循 §6.5 数据与逻辑分离）：

| 资源 | 脚本 | 内容 |
|---|---|---|
| `data/stages/round1.tres` | `stage_data.gd` | 房间 **路径** 列表（存路径而非 Resource 引用，否则加载 StageData 就把所有房间连敌人场景一起拉进来了） |
| `data/stages/round1/roomN.tres` | `room_data.gd` | `bounds`（可活动范围）、`bgTexture/bgPosition/bgScale`、`spawns[]`、`exitX`、`isBossRoom` |
| 房间内的每条刷怪 | `enemy_spawn.gd` | `enemyScene`、`worldPosition`、`hp`、`trigger/triggerX/aliveThreshold/delay`、`enterFrom`、`facing` |

**刷怪方式与时机**（`room.gd` 每物理帧评估）：

| Trigger | 语义 | 用途 |
|---|---|---|
| `ON_ENTRY` | 进房即刷，可再叠 `delay` | 玩家一进门就看到的守军 |
| `AT_PLAYER_X` | 玩家推进到 `triggerX` 才刷 | 原作主要方式：ROM 表里 x 靠后的条目就是走到才出 |
| `WHEN_ALIVE_BELOW` | 场上存活 < `aliveThreshold` 时补这一批 | 增援波，避免一上来全挤在一起 |

`delay` 相对「条件刚成立」计时，条件失效会重新计时。`enterFrom` 决定显形位置：
`PLACED` 原地、`SCREEN_LEFT/RIGHT` 在世界坐标基础上再外移 380px（比半屏多一点），
靠敌人自身的追击 AI 走进画面，不做专门的入场动画状态。

**锁房与切间**（`room_manager.gd`）：进房时把 `bounds` 写给关卡（`Map.playBounds`）
并设 Camera2D 的左右 limit，相机横向跟玩家、被夹在本房内（房间比一屏窄时居中）；
`pending` 清空且无存活即发 `cleared`，玩家继续走到 `exitX` 才真正切下一间，
Boss 房清空直接发 `stageFinished`。上一间的敌人与背景随房间节点一起释放。

**预加载**：`ResourceLoader.load_threaded_request()` 请求下一间的 `.tres`
（连同它引用的敌人场景一起进缓存），切间时 `load_threaded_get()` 取结果，
失败才退回主线程 `load()`。

**坐标折算**：ROM 波次表是 NES 像素，我们的世界按 3 倍缩放、纵深带压缩过，
数据里写的是折算后的世界坐标：

```text
x = nes_x * 3                         （第一关 bg 宽 1016 → 3048）
y = 340 + (nes_y - 112) * 1.8         （地面带 340~450）
```

**第一关内容**（[逆向分析.md](逆向分析.md) §12.17 sections 0/1/2，已剔除 HP=0 的类型 0 事件物）：

| 房间 | section | 敌人（记录 id / 类型 / HP / NES 坐标） | 出场安排 |
|---|---|---|---|
| room1 | 0 | 61/t2/48@(328,136)、1/t1/40@(376,160)、75/t3/64@(584,152)、32/t2/40@(664,174)、100/t2/48@(840,130)、93/t1/48@(976,144) | 前两条 ON_ENTRY（delay 0.8/1.2），中间三条 AT_PLAYER_X（阈值 1432/1672/2200），最后一条 WHEN_ALIVE_BELOW 补增援 |
| room2 | 1 | 77/t5/104@(632,136)、55/t1/40@(680,120) | El Gado 进房 0.3s 后从右侧场外走进；杂兵等存活 <1 再补 |
| room3 | 2 | 19/**t7 Thrasher**/72@(464,136) | Boss 房，进房 1.0s 后出场，朝左面向玩家 |

- 同一类型在不同记录里 HP 不同（t1 有 40 也有 48），所以 **HP 挂在刷怪条目上**，
  `hp = 0` 才回退用敌人场景的默认值。
- 房间沿关卡 x 首尾相接（room1 900~3000、room2 3000~4200、room3 4200~5000），
  section 1/2 的 NES 坐标是各自独立的坐标空间，折算时加了房间原点偏移。
- 背景按房间各自加载：room1 用 `Round 1.png`、room2 用 `Round 1-2.png`、
  room3（Boss 街）用 `Round 1-3.png`。
- 待办：`stageManage.gd` 目前仍是空壳，波次/过关流程与 `stageFinished` 的对接、
  房间切换时的过场、道具掉落触发都还没接；`bgPosition` 是估值，需要开编辑器对齐地面线。

- 碰撞层：玩家侧弹体 `collision_layer = playerHitBox(2)`、`collision_mask = enemy(4)`；
  敌人侧（如 El Gado 飞刀）反过来配。
- SpriteFrames 数据在 `data/sprites/projectile_*_frames.tres`，做到"加一种弹只加数据"。
- **消失条件（2026-11 补）**：`flyBounds` 只判横向，飞出即 `despawn()`；留空时 `setup()`
  自动取投掷者的 `playBounds`（房间制关卡里那就是当前 `RoomData.bounds`，
  由 [room.gd](../MightyFinalFight/script/room.gd) 刷怪时写给敌人、
  [map.gd](../MightyFinalFight/script/map.gd) 写给玩家）。

## 11. 双人与选人

### 已落地（2026-11）

原作只有单打，双人是本项目的扩展（[原作资料.md](原作资料.md) §5、
[后续实现计划.md](后续实现计划.md) 阶段 10）。

**选人画面** `scene/ui/character_select.tscn` + `script/character_select.gd`：

- 三张角色卡（CODY / GUY / HAGGAR），头像取各角色第一条 48×48 帧条的待机首帧
  （`Cody_4_6x1.png`、`Guy_9_6x1.png`、`Haggar_2_6x1.png` 的 AtlasTexture）。
- P1 用 `p1_left/right` 移动光标、`p1_punch` 确认；P2 按自己任意键加入后同样操作；
  双方都确认后按 `start` 开局。确认后光标锁定该角色。
- 界面节点按 `CARDS` 数据表在代码里生成（与 SegmentBar 同样的做法），加角色只改表。
- 流程改为 `welcome → characterSelect → stage1`（此前 welcome 直接进 stage1）。

**选择结果传递**：`Game` 单例新增 `CharacterId` 枚举、`playerCount` 与
`characterIds`（各槽位选谁）、`characterScenePaths` / `characterNames` 两张表，
以及 `selectedScenePath(slot)` / `setSelection()` / `resetSelection()`。
按 §6.4，Autoload 的枚举值不是编译期常量，所以这些表写 `var` 不写 `const`。

**关卡按选择生成玩家**：`stage1.tscn` 不再写死 `codyP1`，改由 `stage1.gd` 的
`spawnPlayers()` 按 `Game.playerCount` 实例化，出生点 `[930, 986]`（都在 room1 的
bounds 内，避免第一次移动就被钳回来）。
`playerId` 必须在 `add_child` **之前**设置——`FightObject._ready()` 里就按它派生
`keyMapPrefix`，晚设会导致 2P 读不到自己的按键。

**多人适配的关卡侧改动**：

- `Player.alivePlayers(tree)` 静态方法统一取存活玩家。
- 房间触发与出口判定用「推进最前（x 最大）」的存活玩家，避免落在后面的人把波次卡住。
- 相机按存活玩家的**中点**跟随并夹在房间范围内（单人即本人）。
- 敌人锁定本来就是就近取（`Enemy.findTarget`），双人后自动分兵。

**已知缺口**：命数/续关的多人规则（原作单打，2P 掉线补位规则待定）；
两名玩家的身体互相阻挡（`CharacterBody2D` 默认同层同掩码），要不要让队友穿透
属于手感调优，暂未改；选人画面的角色立绘/音效待接。
