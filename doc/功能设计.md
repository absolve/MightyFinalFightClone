## 1. 搓招 / 按键连招系统（核心机制）

### 1.1 功能说明

「搓招」指玩家通过特定方向键 + 攻击键的时序组合触发必杀技，是清版动作游戏的核心手感来源。
> 注意：本作（NES 版）原作**并没有街霸式搓招**。原作特殊技输入为「B → 前」的时机型指令，
> 不是方向键序列；Cody/Haggar 需 LV4，Guy 日版说明书为 LV1（英文攻略多写 LV4）。
> 特殊技包括 Cody「Tornado Sweep / Rising Uppercut」、Guy「Sonic Kick（英：Tornado Kick）/ Fire Kick」、
> Haggar「Scramble Haggar Press（英：Running Clothesline）」；另有 A+B 旋转必殺技（消耗自身体力）。
> 原作的普通连击是**命中驱动**的 4 段连击（第 4 段高伤击倒，第 3 段后可投技），不是按输入固定递进。
> 本项目搓招系统是**扩展玩法**（沿用既有 godot3 demo 设计），不是对原作的还原；连击则按原作命中驱动实现。
> 详见 [原作资料.md](原作资料.md) §3.2-3.8。

示例（沿用既有 godot3 demo 的设计）：
- `→ + 拳` → skill1
- `→ ← + 拳` → skill2
- `↑ ↓ + 拳` → skill3

### 1.2 既有实现回顾（godot3，`F:\godotTestDemo\godot3inputCombo`）

| 文件 | 职责 |
|------|------|
| `autoload/game.gd` | 硬编码 `combos` 数组：`{name, combos:[[序,序],...], priority}` |
| `script/player.gd` | 维护 `inputList` 环形缓冲（max 50）；`checkCombo()` 用字符串子串匹配；`aniFinish()` 动画结束回调驱动连段 |
| `script/main.gd` | 独立维护一份 inputList（max 7）仅用于 UI 显示 |
| `scene/player.tscn` | AnimationTree + AnimationNodeStateMachine，idle/move/punch1-3/skill1-3 状态与转移 |

**核心匹配逻辑**（`player.gd::checkCombo`）：
```gdscript
var temp = "".join(inputList)              # 拼成 "leftpunchright"
for i in combo:
    var str1 = "".join(y)                   # "leftpunch"
    if temp.find_last(str1) != -1:          # 子串命中
        existCombo.append(i)
existCombo.sort_custom(self, "sortCombo")   # 按 priority 降序
animation_state.travel(existCombo[0].name)
```

**缓冲衰减**：
```gdscript
timer += 1
if timer > timeDelay:      # timeDelay=30 帧 ≈ 0.5s
    timer = 0
    inputList.pop_back()   # ⚠ 弹出的是最新一项
```

### 1.3 既有实现的问题

1. **衰减方向错误**：`add2InputList` 用 `push_back` 追加，而衰减用 `pop_back()` 移除最新项——应为 `pop_front()` 移除最旧项，否则玩家最新的有效输入会被先丢弃。
2. **字符串子串匹配有歧义**：`"leftpunch"` 会命中 `"left"` + 任意 + `"punch"` 的任意间隔组合，无法保证时序相邻；`"down"` 与 `"punch"` 拼接后也可能误匹配 `"downpunch"` 子串。
3. **无时间窗口约束**：只按帧数粗略衰减，没有「单次搓招必须在 X 毫秒内完成」的判定，慢速连点也能凑出必杀。
4. **连招定义硬编码在 autoload**：加新招要改 `game.gd`，无法数据驱动，不符合扩展偏好。
5. **输入缓冲重复**：`player.gd` 与 `main.gd` 各存一份 inputList，状态不同步。
6. **无多玩家支持**：单 buffer，P2 无法复用。
7. **`existCombo[0].name` 未校验非空**：极端情况下 `existCombo` 排序后仍可能取到错。

### 1.4 改进方案（Godot 4，推荐用于本项目）

设计目标：**解耦、数据驱动、时间戳衰减、严格时序匹配、多玩家就绪**。

#### 架构分层

```
InputRecorder (autoload)     ─ 单例，按 playerId 维护输入缓冲，时间戳衰减
        ↓ signal: input_recorded(player_id, action)
ComboDef (Resource)          ─ .tres 文件，定义单招：name/inputs/priority/window
ComboMatcher (autoload/类)    ─ 取 buffer + combo 列表，返回最佳匹配
player 的 attack/idle state   ─ 订阅信号，命中则 transition_to(skill_state)
```

#### (A) InputRecorder —— 输入缓冲单例

改进点：用时间戳而非帧计数；过期自动剔除；每玩家独立。

```gdscript
# autoload/input_recorder.gd
extends Node
class_name InputRecorder

# 每条输入：动作名 + 记录时刻（秒）
class InputEntry:
    var action: String
    var time: float
    func _init(a: String, t: float) -> void:
        action = a; time = t

# buffer_window：单条输入最长保留时间（秒），超过自动剔除
@export var buffer_window: float = 0.5
# 每玩家的缓冲
var _buffers: Dictionary = {}   # playerId -> Array[InputEntry]

func record(player_id: int, action: String) -> void:
    if not _buffers.has(player_id):
        _buffers[player_id] = []
    _buffers[player_id].append(InputEntry.new(action, Time.get_ticks_msec() / 1000.0))
    input_recorded.emit(player_id, action)

# 取某玩家当前有效缓冲（已剔除过期项），返回动作名数组
func get_buffer(player_id: int) -> Array[String]:
    var arr: Array[String] = []
    if not _buffers.has(player_id):
        return arr
    var now: float = Time.get_ticks_msec() / 1000.0
    var buf: Array = _buffers[player_id]
    # 移除过期（从头部，最旧）
    while buf.size() > 0 and now - buf[0].time > buffer_window:
        buf.pop_front()
    for e in buf:
        arr.append(e.action)
    return arr

func clear(player_id: int) -> void:
    if _buffers.has(player_id):
        _buffers[player_id].clear()

signal input_recorded(player_id: int, action: String)
```

> 关键差异：`pop_front()` 移除最旧项（修正 godot3 的方向错误）；按真实时间而非帧数，帧率波动下行为一致。

#### (B) ComboDef —— 数据驱动招式定义

```gdscript
# script/combo_def.gd
extends Resource
class_name ComboDef

@export var name: StringName        # 必杀名，对应 AnimationTree 状态
@export var inputs: Array[StringName] = []  # 时序输入，如 ["right","left","punch"]
@export var priority: int = 0       # 数字大优先
@export var time_window: float = 0.4 # 该招必须在 0.4s 内完成
@export var damage: int = 10
@export var cost_hp: int = 0        # 消耗自身血量（原作必杀扣血）

# 供编辑器创建 .tres：res://data/combos/cody_skill1.tres 等
```

招式表改用 `res://data/combos/<char>/*.tres`，加新招只加资源文件、零代码改动（呼应数据驱动偏好）。

#### (C) ComboMatcher —— 严格时序匹配

改进点：做**后缀严格匹配**——只有缓冲末尾 N 项与招式输入序列完全一致才算命中，避免子串歧义。

```gdscript
# script/combo_matcher.gd
class_name ComboMatcher

# combos: Array[ComboDef]  buffer: Array[String]
static func match(combos: Array, buffer: Array[String]) -> ComboDef:
    var best: ComboDef = null
    for def in combos:
        var seq: Array = def.inputs
        if seq.size() == 0 or seq.size() > buffer.size():
            continue
        # 取缓冲末尾 len(seq) 项做严格比较
        var start: int = buffer.size() - seq.size()
        var ok: bool = true
        for i in seq.size():
            if buffer[start + i] != seq[i]:
                ok = false
                break
        if ok:
            # 优先取更长的招式（输入更多更难搓），同长度取 priority 高的
            if best == null or seq.size() > best.inputs.size() \
               or (seq.size() == best.inputs.size() and def.priority > best.priority):
                best = def
    return best   # 可能为 null
```

> 关键差异：严格后缀匹配替代 `find_last` 子串，杜绝误判；长序列优先（避免 `→拳` 抢掉 `→←拳`）。

#### (D) 玩家侧集成（接入状态机）

```gdscript
# script/states/idle_state.gd （节选）
extends "res://script/state.gd"

func handle_input(_event: InputEvent) -> void:
    var p = player
    if Input.is_action_just_pressed("%s_punch" % p.keyMapPrefix):
        InputRecorder.record(p.playerId, "punch")
        # 先查必杀
        var matched := ComboMatcher.match(p.combos, InputRecorder.get_buffer(p.playerId))
        if matched:
            state_machine.transition_to("skill", {skill = matched.name})
            InputRecorder.clear(p.playerId)
        else:
            state_machine.transition_to("attack", {hit = 1})
    # 方向键也录入缓冲（供搓招判定）
    for a in ["up","down","left","right"]:
        if Input.is_action_just_pressed("%s_%s" % [p.keyMapPrefix, a]):
            InputRecorder.record(p.playerId, a)
```

```gdscript
# script/states/attack_state.gd （节选，连段）
func enter(_prev, data) -> void:
    hit_count = data.get("hit", 1)
    player.ani.play("punch%d" % hit_count)

func on_animation_finished(anim_name) -> void:
    if not anim_name.begins_with("punch"):
        return
    var buf := InputRecorder.get_buffer(player.playerId)
    # 连段：缓冲末尾是 punch 且未到第 3 段
    if buf.size() > 0 and buf.back() == "punch" and hit_count < 3:
        InputRecorder.clear(player.playerId)
        state_machine.transition_to("attack", {hit = hit_count + 1})
    else:
        state_machine.transition_to("idle")
```

#### (E) AnimationTree 状态机

沿用既有 `player.tscn` 的 AnimationNodeStateMachine 结构（idle/move/punch1-3/skill1-3），通过 `state_machine.travel(name)` 驱动，无需改动。

### 1.5 与原实现的对照表

| 维度 | godot3 既有 | godot4 改进 |
|------|-------------|-------------|
| 衰减 | 帧计数 + `pop_back()`（方向错） | 时间戳 + `pop_front()`（最旧优先） |
| 匹配 | 字符串子串 `find_last` | 后缀严格逐项比较 |
| 歧义 | `→拳` 可能误命中 `→←拳` | 长序列优先 + 严格后缀，无歧义 |
| 招式定义 | 硬编码 autoload 数组 | `.tres` 资源文件，数据驱动 |
| 多玩家 | 单 buffer | 按 playerId 分桶 |
| 输入源 | player/main 各存一份 | InputRecorder 单一来源 + 信号广播 |
| 时间窗口 | 无 | ComboDef.time_window 可单招配置 |

### 1.6 落地步骤（对应 [后续实现计划.md](后续实现计划.md) 阶段 1-2）

1. 新建 `autoload/input_recorder.gd`，在 `project.godot` 注册为 `InputRecorder`。
2. 新建 `script/combo_def.gd`（Resource 子类）。
3. 新建 `script/combo_matcher.gd`（静态工具类）。

6. 建 `data/combos/cody/`、`guy/`、`haggar/` 目录放招式 `.tres`。

## 2. 玩家移动与状态机

### 设计
- 沿用既有 `state.gd` / `stateMachine.gd` 框架，补 `transition_to(path, data)` 方法。
- 状态：idle / walk / jump / attack(1-3 连段) / hurt / hit_fly / skill / grab / throw。
- 移动：平面四向（WASD），速度 300；跳跃用既有 zVec + gravity 模拟伪 3D 落地阴影。
- 朝向 `faceDir` 控制贴图 `flip_h` 与 hitBox 偏移。

### 实现要点
- `object.gd` 增 `faceDir`、`maxHp`、`takeDamage()`、`invincibleTimer`。
- `playerState.gd` 拆成多个子状态文件，每个独立处理输入与动画。
- 跳跃落地播放 `落地.wav`，起跳播放 `起跳.wav`（接音频系统后）。

## 3. 战斗与命中判定

### 设计
- `object.tscn` 已有 hitBox / hurtBox（Area2D），补 CollisionShape2D 尺寸。
- layer/mask：hitBox(layer=playerHitBox, mask=enemy) ↔ enemy hurtBox(layer=enemy, mask=playerHitBox)。
- 命中流程：攻击动画关键帧启用 hitBox → `area_entered` → 调 `target.takeDamage(dmg, fromDir)` → 目标入 hurt/hit_fly 状态。
- 连段：attack 状态 1→2→3 段递进，第 3 段击飞（见 §1 攻击状态示例）。

### 实现要点
- AnimationPlayer 用 method track 在攻击帧调用 `enable_hitbox(true/false)`。
- 命中后短暂顿帧（`Engine.time_scale` 或暂停一帧）增强手感。

## 4. 敌人 AI

### 设计
- `enemy.gd extends object`，状态：idle/pursue/attack/hurt/dead。
- 追击：按玩家位置走 `move_and_slide`，进入攻击距离则 attack。
- 死亡：播放 `敌人倒地.wav` → 掉落概率生成 item → 移除节点。
- 数据驱动：`enemy_def.tres`（hp/attack/speed/ai_type）。
