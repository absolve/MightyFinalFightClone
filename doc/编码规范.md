# MightyFinalFightClone 代码设计规范（Code Design Guidelines）

> 本文档是本项目的**唯一编码规范**：手写代码、AI 生成代码、代码审查一律以它为准。
> 目的是让不同时间、不同人（或不同 AI）写出来的代码风格保持一致，降低阅读与维护成本。
> 参考自 `F:\machine-TD\code_design.md`，按本项目实际情况裁剪调整。

| 项目 | 内容 |
| --- | --- |
| 适用项目 | MightyFinalFightClone（Godot 4.6，GDScript）—— NES《快打旋风》复刻 |
| 文档版本 | v1.0 |
| 更新日期 | 2026-10-12 |
| 主要依据 | Godot 官方《GDScript style guide》《Static typing in GDScript》+ 本项目既定约定 |

> ⚠️ **务必注意**：文中标注「**本项目约定**」的条目，是对 Godot 官方风格的**有意偏离**。
> 生成或审查代码时**不要**按官方默认风格去"纠正"它（例如把 camelCase 改回 snake_case、把内置函数挪到文件开头、把显式类型改成 `:=`），否则会破坏全文一致性。

> **现状说明**：现有早期代码（`object.gd`、`playerState.gd`、`game.gd` 等）风格尚未统一：
> 枚举名用 camelCase、`class_name` 用 camelCase、多数变量无类型注解、`#` 后无空格。
> 新写代码一律按本规范执行；改造旧文件时**只改本次触碰到的部分**，不要为统一风格做全量重命名。

## 0. 强制规则速查（写代码前必读）

> 下面 11 条是最容易"跑偏"的地方，生成代码前先过一遍。

| # | 规则 | 备注 |
| --- | --- | --- |
| 1 | 函数、变量用 **camelCase** | 官方是 snake_case，**本项目不用** |
| 2 | 常量用 **CONSTANT_CASE**，类名/枚举名用 **PascalCase** | 见 §2 |
| 3 | 不得占用 Godot 内置名 | 如 `position`/`scale`/`name`/`visible`/`get`/`set` |
| 4 | 顺序：`@onready` → `_ready` → 自定义函数 → **其它内置虚函数放最后** | 本项目约定，与官方相反 |
| 5 | 成员 / 参数 / 返回值**显式声明类型** | 局部变量可省略类型；不用 `:=` 推断 |
| 6 | 场景能设的属性在**编辑器 Inspector** 里设 | 不要全塞进代码 |
| 7 | 可复用功能先做**基础场景 + 基础脚本** | 子类只覆盖差异（如 `object.gd` + `cody.gd`） |
| 8 | 缩进 **Tab**、行宽 ≤ 100、UTF-8 无 BOM、LF 换行 | 见 §1.1 |
| 9 | 注释符号后**必须一个空格**：`# 文字`、`## 文字` | 被注释掉的代码除外：`#print(...)` |
| 10 | 节点引用用 `@onready` + `$路径`，不要在 `_process` 里 `get_node()` | 见 §7.1 |
| 11 | 模块间通信用 `signal`，少用直接引用 | 信号名过去式 + camelCase |

## 1. 格式规范

### 1.1 文件与编码

- 换行用 **LF**（`\n`），不要 CRLF / CR。
- 文件结尾保留**一个**换行。
- 编码 **UTF-8，无 BOM**。
- 缩进用 **Tab**，不用空格。
- 保存前用编辑器格式化：脚本编辑器内 `Ctrl + Alt + L`。

### 1.2 缩进

- 每个代码块比外层多一级缩进。
- 换行的**连续行**用**两级**缩进，以便与普通代码块区分。
- **例外**：数组、字典、枚举的续行只用**一级**缩进。

```gdscript
# 好：普通连续行用 2 级缩进
player.set_velocity(Vector2(
		moveX * speed,
		moveY * speed,
))

# 好：数组 / 字典 / 枚举用 1 级缩进
var combos = [
	"skill1",
	"skill2",
]
```

### 1.3 空行

- 函数之间、类定义之间空**两行**；函数内部用**一行**分隔逻辑段落。
- 成员声明块内部（signal/enum/const/export/var/@onready）不强制空行。

### 1.4 行宽

- 单行**不超过 100 字符**，尽量控制在 80 以内。

### 1.5 一行一语句

```gdscript
# 好
if player.hp <= 0:
	player.die()

# 坏
if player.hp <= 0: player.die()
```

唯一例外是三元表达式：

```gdscript
nextState = "idle" if isOnFloor else "fall"
```

### 1.6 多行语句排版

长条件、长表达式用**括号**换行（优于反斜杠），并把 `and` / `or` 放在**续行行首**。

```gdscript
if (
		player.invincible == false
		and player.hp > 0
		and player.state == Game.PlayerState.IDLE
):
	player.takeDamage(dmg)
```

### 1.7 不要多余的括号

```gdscript
# 好
if isOnFloor():
	queue_free()

# 坏
if (isOnFloor()):
	queue_free()
```

### 1.8 布尔运算符

用 `and` / `or` / `not`，不要 `&&` / `||` / `!`。

### 1.9 注释

- 普通注释用 `#`、文档注释用 `##`，符号后**必须跟一个空格**。
- 被注释掉的**代码不加空格**：`#print("disabled")`。
- 区域注释 `#region` / `#endregion` 顶格写，**不加**空格。
- 优先把注释写在**独立一行**；行尾注释只用于很短的说明。
- 注释用中文，说明**为什么**这么做，而不是复述代码在做什么。

> **现状**：`object.gd` 等旧文件存在 `#血量`、`#是否无敌` 这类 `#` 后无空格的写法，触碰时一并修正。

### 1.10 空白 / 引号 / 数字

- 运算符两侧、逗号后各留一个空格；不要为"对齐"加多余空格。
- 单行字典 `{ key = "value" }` 花括号内侧各留一个空格，以便与数组区分。
- 字符串默认用**双引号**；仅当能减少转义时才用单引号。
- 浮点数不省略前后 0：写 `0.234`、`13.0`（不写 `.234`、`13.`）。
- 十六进制用小写：`0xfb8c0b`。
- 大数字用下划线分隔：`1_234_567_890`（小于 100 万的数一般不必）。

> **现状**：旧代码 `var hp=0`、`var speed=300` 等运算符两侧无空格，触碰时一并修正为 `var hp: int = 0`。

### 1.11 尾随逗号

多行数组 / 字典 / 枚举的最后一项**加尾随逗号**（便于 diff 与增删条目）；单行列表**不加**。

```gdscript
# 好（多行，带尾随逗号）
var comboInputs = [
	"left",
	"right",
	"punch",
]

# 好（单行，不带）
var comboInputs = ["left", "right", "punch"]
```

## 2. 命名规范

### 2.1 总表

| 对象 | 本项目约定 | 示例 | 来源 |
| --- | --- | --- | --- |
| 函数 | **camelCase** | `func loadStage()` | 本项目约定（官方为 snake_case） |
| 变量 | **camelCase** | `var playerNode` | 本项目约定（官方为 snake_case） |
| 私有函数 / 变量 | **camelCase，不加 `_` 前缀** | `var finishChecking`、`func onEnemyDied()` | 本项目约定（官方为 `_snake_case`） |
| 常量 | **CONSTANT_CASE** | `const MAX_SPEED = 300` | 官方 |
| 类名 `class_name` | **PascalCase** | `class_name PlayerState` | 官方 |
| 节点名 | **PascalCase** | `Body`、`StateMachine`、` HurtBox` | 官方（新建场景尽量照此） |
| 枚举名 | **PascalCase，单数** | `enum State` | 官方 |
| 枚举成员 | **CONSTANT_CASE** | `State.IDLE` | 官方 |
| 信号 | **camelCase，过去式** | `signal enemyDied` | 官方过去式 + 本项目 camelCase |
| Autoload 单例 | **PascalCase** | `Game`、`InputRecorder` | 官方 |
| 输入动作名 | **snake_case + p1_ 前缀** | `p1_left`、`p1_punch` | 本项目约定（沿用 project.godot 现状） |
| 脚本 / 场景文件名 | **snake_case** | `player_state.gd`、`stage1.tscn` | 官方（避免跨平台大小写问题） |

> **例外**：**Godot 引擎回调必须保留 `_` 前缀**（`_ready`、`_process`、`_physics_process`、`_input`、`_unhandled_input`、`_draw`、`_notification`、`_enter_tree`、`_init` 等），它们是引擎按名字调用的，改名会失效。

> **现状**：旧代码 `class_name stateMachine`、`class_name state`、`enum playerState`、`enum PlayId` 不符合 PascalCase 规范。
> 新建类/枚举一律按上表执行；改造旧文件时只改本次触碰到的部分。

注意有些变量和函数名字是 Godot 组件的属性名字（如 `position`、`velocity`、`animation`），这些不用修改，是引擎提供的。
函数名不能跟变量名和局部变量名一样。

### 2.2 禁止占用 Godot 内置名（本项目约定，强制）

自定义变量 / 函数**不得**与 Godot 内置属性、方法、常量、信号重名，否则会产生遮蔽（shadowing）警告，严重时导致运行期行为异常。

常见必须避开的名称（非完整清单）：

- **节点通用属性**：`name`、`owner`、`process_mode`、`scene_file_path`
- **`Node2D` / `Node3D` 变换与显示**：`position`、`global_position`、`rotation`、`scale`、`skew`、`transform`、`z_index`、`visible`、`modulate`
- **`Control`**：`size`、`pivot_offset`、`focus_mode`、`theme`
- **`CollisionObject2D`**：`collision_layer`、`collision_mask`
- **`CharacterBody2D`**：`velocity`（本项目用 `vec` 规避）、`move_and_slide`、`set_velocity`
- **常见方法**：`get`、`set`、`connect`、`call`、`free`、`queue_free`、`duplicate`、`to_string`
- **全局函数**：`abs`、`min`、`max`、`clamp`、`lerp`、`randf`、`randi`、`print`、`range`、`sign`、`snapped`

> 拿不准就去 Godot 类文档里搜同名项；编辑器出现 "shadowed variable" 警告即说明已踩线。

> **现状**：`object.gd` 已用 `vec` 规避 `velocity`、`keyMapPrefix` 规避内置，做法正确；`state` 字段名虽与类名 `state` 冲突但不严重（不同作用域），建议改名为 `currentState`。

## 3. 类型与静态类型

### 3.1 所有声明都写显式类型（本项目约定）

> 官方风格是「能推断就用 `:=`」，**本项目相反**：为了可读性与统一，**成员变量、函数参数、返回值**一律写显式类型，不使用 `:=` 推断。
>
> **例外**：函数内部的**局部变量**可以不写类型（如 `var count = 0`），就近声明即可。

```gdscript
# 好
@export var hp: int = 0
var speed: float = 300.0
var vec: Vector2 = Vector2.ZERO
var combos: Array = []
var state: Game.PlayerState = Game.PlayerState.IDLE

const MAX_HP: int = 100
const GRAVITY: float = 980.0

func takeDamage(amount: int) -> void:
	pass

func getVelocity() -> Vector2:
	return vec
```

```gdscript
# 坏：用 := 或干脆不写类型
@export var hp := 0
var speed = 300
func takeDamage(amount):
	pass
```

> **现状**：`object.gd` 的 `@export var hp=0`、`var speed=300`、`playerState.gd` 的 `var player` 都缺类型注解；`stateMachine.gd` 的 `initialState: NodePath` 已正确。触碰旧文件时补类型。

### 3.2 具体类型标注

- 变量 / 参数 / 返回值：`名字: 类型`；返回类型用 `-> 类型`。
- 数组元素类型：`Array[ComboDef]`；字典键值类型：`Dictionary[String, int]`。
  **不支持嵌套**，如 `Array[Array[int]]` 是非法的。
- 即使不打算做泛型约束，成员变量也至少写 `Array` / `Dictionary`，不要留裸 `var`（局部变量除外）。
- `get_node()` 无法被推断类型，必须显式声明：

```gdscript
@onready var bodyNode: Node2D = $body
@onready var ani: AnimatedSprite2D = $body/ani
```

### 3.3 空值安全

- 用 `as` 强转会**静默变 `null`**：拿到结果后必须判空再使用。
- 需要暴露错误时，用 `is` / `is not` + `push_error()`，比 `as` 更安全。

```gdscript
var enemy = body as Enemy # 局部变量，可以不写类型
if enemy == null:
	return
enemy.takeDamage(10)
```

### 3.4 建议开启的警告

「项目设置 → Debug → GDScript」（需开启高级设置）中启用：
`UNTYPED_DECLARATION`、`INFERRED_DECLARATION` 以及 `UNSAFE_*` 系列，让编辑器帮忙盯住类型问题。

## 4. 文档注释

### 4.1 写法

- 文档注释用 `##`，写在**被说明成员的正上方**。
- 推荐分三块：**脚本类概述 / 脚本类详细描述 / 教程与特殊标记**，块与块之间用一行空的 `##` 分隔。
- 普通块内注释用 `#`；只有会被导出到文档的内容才用 `##`。

```gdscript
extends CharacterBody2D
## 战斗对象基类：管理血量、移动、命中判定与状态机入口。
##
## 所有可受伤对象（玩家 Cody/Guy/Haggar、敌人、Boss）都继承本脚本，
## 只需覆盖差异方法（如 [method takeDamage] 的击飞逻辑）。
##
## @experimental: z 轴跳跃模拟尚未稳定
```

### 4.2 特殊标记

特殊标记须写在文本行开头（可含前导空格），以 `@` 开头，后接标记名。

| 用途 | 标记 |
| --- | --- |
| 概述 | 无标记，位于文档开头部分 |
| 描述 | 无标记，用一行空的文档注释行与概述隔开 |
| 文字教程 | `@tutorial: https://example.com` 或 `@tutorial(标题写在此处): https://example.com` |
| 已弃用 | `@deprecated` / `@deprecated: 请改用 [AnotherClass]。` |
| 实验性 | `@experimental` / `@experimental: 该类不稳定` |

### 4.3 交叉引用

文档注释内用 BBCode 引用其它符号，方便在编辑器里跳转：
`[method _ready]`、`[member hp]`、`[signal enemyDied]`、`[Enemy]`、`[b]粗体[/b]`。

## 5. 代码顺序

### 5.1 脚本内顺序（本项目约定）

> **本项目约定**：自定义函数放**前面**，Godot 内置虚函数放**末尾**。
> 这与官方推荐（`_init` / `_ready` 在最前）**正好相反**——生成代码时不要"纠正"它。

约定顺序：

```text
01. @tool / @icon / @static_unload
02. class_name
03. extends
04. ## 类文档注释
05. signals
06. enums
07. constants
08. @export 变量
09. 普通成员变量（public 在前，private 在后；private 不加 `_` 前缀）
10. @onready 变量
11. _ready()（或初始化函数）
12. 自定义函数（public 在前，private 在后）
13. 其它 Godot 内置虚函数 / 回调（放最后）：
      _init / _enter_tree / _process / _physics_process /
      _input / _unhandled_input / _draw / _notification ……
14. 内部类（inner class）
```

示例：

```gdscript
extends CharacterBody2D
class_name Player
## 玩家基类：管理血量、移动、攻击与搓招输入。

signal hpChanged(currentHp: int)

enum State {
	IDLE,
	WALK,
	ATTACK,
	HURT,
	JUMP,
	SKILL,
}

const MAX_HP: int = 100
const GRAVITY: float = 980.0

@export var hp: int = 100
@export var speed: float = 300.0
@export var playerId: Game.PlayId = Game.PlayId.P1

var state: State = State.IDLE
var faceDir: int = 1
var vec: Vector2 = Vector2.ZERO
var inAir: bool = false
var zVec: float = 0.0

@onready var bodyNode: Node2D = $body
@onready var ani: AnimatedSprite2D = $body/ani

func _ready() -> void:
	keyMapPrefix = "p1" if playerId == Game.PlayId.P1 else "p2"

# ---- 自定义函数放前面 ----

func takeDamage(amount: int) -> void:
	hp = max(hp - amount, 0)
	hpChanged.emit(hp)
	if hp <= 0:
		die()


func die() -> void:
	queue_free()


func moveX(delta: float) -> void:
	var xDir: float = Input.get_axis("%s_left" % keyMapPrefix, "%s_right" % keyMapPrefix)
	vec.x = xDir * speed

# ---- Godot 内置虚函数放最后 ----

func _physics_process(delta: float) -> void:
	moveX(delta)
	vec = move_and_slide()
```

### 5.2 成员变量与局部变量

- 只在单个方法里用到的值，**不要**提成成员变量，就写成局部变量。
- 局部变量**就近声明**，靠近首次使用处。
- `@onready` 只用于缓存节点引用（它在 `_ready` 之前求值），不要在 `_init` 里用 `$路径`。

> **现状**：`object.gd` 把 `state`、`zPos`、`level` 等都提成成员但部分未使用，后续重构时下沉为局部变量。

## 6. 项目架构设计

### 6.1 目录结构

```text
MightyFinalFightClone/          仓库根
├── .git/                        Git 版本控制（仓库级）
├── doc/                         项目文档
│   ├── 项目现状.md
│   ├── 后续实现计划.md
│   ├── 功能设计.md
│   ├── 编码规范.md              本文件
│   └── code_design.md
└── MightyFinalFight/            Godot 工程根
    ├── project.godot
    ├── default_env.tres
    ├── icon.png / .import
    ├── .gitignore
    ├── autoload/                全局单例：Game、（待加）InputRecorder、Audio……
    ├── font/                    字体（PressStart2P）
    ├── scene/                   场景，按类别分子目录（待加 enemy/、ui/、fx/……）
    │   ├── bg.tscn  map.tscn  object.tscn  stage1.tscn  welcome.tscn
    │   ├── cody.tscn  guy.tscn  haggar.tscn  playerState.tscn
    │   ├── item.tscn  state.tscn  stateMachine.tscn  stageManage.tscn  testScene.tscn
    │   └── （后续）ui/hud.tscn  ui/characterSelect.tscn  enemy/*.tscn
    ├── script/                  脚本，与 scene/ 一一对应
    │   ├── object.gd  playerState.gd  state.gd  stateMachine.gd  map.gd  bg.gd
    │   ├── cody.gd  guy.gd  stage1.gd  stageManage.gd  welcome.gd  item.gd
    │   └── （后续）states/*.gd  enemy.gd  combo_def.gd  combo_matcher.gd
    ├── sound/                   音效资源（22 个 wav/mp3，已导入）
    ├── sprite/                  美术资源（player/enemy/item/bg/HUD/Cutscenes）
    └── .import/                 Godot 导入缓存
```

规则：

1. **新文件放对应类别的子目录**；移动/改名文件后必须同步更新所有引用（`preload`、`.tscn` 的 `[ext_resource path]`、`project.godot` 的 autoload、`uid://`）。
2. 场景名与脚本名对应（`cody.tscn` ↔ `cody.gd`），便于查找。
3. 状态机子状态建议放 `script/states/`（`idle_state.gd`、`walk_state.gd`、`attack_state.gd`……）。
4. 搓招相关数据放 `MightyFinalFight/data/combos/<角色>/*.tres`（见 [功能设计.md](功能设计.md) §1.4）。

### 6.2 复用：基础场景 + 基础脚本（本项目约定）

> 出现可复用的功能时，**先做一份基础场景 + 基础脚本**，后续同类对象继承 / 实例化它，只覆盖差异。

- 已有范例：
  - 战斗对象：`scene/object.tscn` + `script/object.gd`（CharacterBody2D 基类，含 hp/speed/gravity/vec/inAir/zVec/hitBox/hurtBox/AnimationPlayer/AnimationTree），子类 `cody.gd`/`guy.gd` 用 `extends "res://script/object.gd"`。
  - 状态：`script/state.gd`（基类）+ `script/playerState.gd`（玩家移动逻辑）+ `script/stateMachine.gd`（驱动器）。
  - 关卡：`script/map.gd` + `scene/map.tscn`，子类 `stage1.gd extends map`。
- 做法：
  - 子场景用**继承场景**（Inherit Scene）或直接实例化基础场景；
  - **数值差异优先在子场景的 Inspector 里改**，不要在子脚本里重新赋值；
  - 只有**行为差异**才在子脚本里覆盖方法。
- 新增敌人 / Boss 时，记得同步登记数据表（`Game` 的招式列表、波次配置等），做到"只加数据、不加逻辑"。

### 6.3 节点与属性设置（本项目约定）

> 在场景里添加节点时，属性**尽量在编辑器 Inspector 里直接设置**，不要全用代码赋值。

- 位置、尺寸、颜色、层级、碰撞层、锚点、主题等**静态属性** → Inspector。
- 只有**运行期才确定**的值才在代码里设置。
- 好处：所见即所得、代码更短，并避免"代码赋值覆盖场景配置"这类问题。

```gdscript
# 好：静态属性都在场景里设好，代码只做运行期逻辑
func _ready() -> void:
	pass

# 坏：把本该在场景里设的静态属性硬编码进代码
func _ready() -> void:
	position = Vector2(100, 200)
	modulate = Color.RED
	collision_layer = 2
```

> **⚠️ 场景资源文件里不能写注释。** `.tscn` / `.tres` 是 Godot 的**文本资源格式**，
> 它**不支持 `#` 注释** —— 写了会让整个资源报 `Parse Error: Parse error.`（带行号），
> 场景直接加载失败。要给某个属性留说明，写到**脚本的 `##` 文档注释**、
> `doc/功能设计.md` / `doc/编码规范.md`，或提交信息里。

### 6.4 单例（Autoload）

- 跨场景共享的状态与事件放在 `autoload/`，用 **PascalCase** 命名，全局直接访问（`Game`、（待加）`InputRecorder`、`Audio`……）。
- 单例之间不要强耦合；对外用 `signal` 暴露事件，其它系统监听而非直接调用。
- 注意：**Autoload 的枚举值不是编译期常量**，所以用它做 key 的表只能写 `var`，不能写 `const`。
- `project.godot` 中 autoload 注册路径需相对 Godot 工程根（`res://autoload/xxx.gd`）。

> **现状**：`Game` 已注册，定义了 `playerState`/`direction`/`PlayId`/`gameObjType` 枚举。后续按 §2.1 把枚举名改为 PascalCase（`PlayerState`、`Direction`、`PlayId`）时，需同步更新 `project.godot` 与所有引用。

### 6.5 数据与逻辑分离

- 数值、敌人表、招式表、关卡波次配置等**数据**集中声明（`Resource` / `.tres` / `.json`），逻辑只读数据，不硬编码分支。
- 目标：**新增条目只加数据、不改逻辑**（如往 `data/combos/cody/` 加一条 `.tres` 即多一招必杀）。
- 关卡波次建议用 `data/stages/round1.json` 或 `StageData` Resource。

### 6.6 信号驱动

- 模块间通信优先用 `signal`，少用直接引用。
- 信号名用**过去式 + camelCase**：`enemyDied`、`comboMatched`、`stageFinished`、`hpChanged`。
- 在 `_ready()` 里连接；连接到节点的信号会在节点释放时自动断开，无需手动 `disconnect`。
- 自定义信号要显式声明，参数尽量带类型注解。

```gdscript
signal hpChanged(currentHp: int)
signal comboMatched(skillName: StringName, playerId: int)
```

### 6.7 分组与物理层

- 同类对象入组（`enemy`、`player`、`item`……），方便 `get_nodes_in_group()` 批量查找。
- 物理层严格按 `project.godot` 里 `layer_names` 的定义使用，不要凭记忆写数字。

| 层 | 名称 | 用途 |
| --- | --- | --- |
| 1 | `player` | 玩家/角色碰撞体 |
| 2 | `playerHItBox` | 玩家攻击判定（**注：现有拼写含大写 I，是历史 typo，触碰时可修正为 `playerHitBox` 并同步 project.godot**） |
| 3 | `enemy` | 敌人碰撞体 |
| 4 | `enemyHItBox` | 敌人攻击判定（同上 typo） |

> 修正拼写时需同时改 `project.godot` 的 `[layer_names]` 与所有 `.tscn` 里写死的 `collision_layer`/`collision_mask` 数值引用。

### 6.8 国际化（可选，暂不强制）

- 若后续需要多语言，玩家可见文案用 `tr("key")`，文案集中在 `MightyFinalFight/lang/language.csv`。
- 当前项目面向中文玩家，标题画面英文文案（"PUSH START"、"capcom co., ltd. 1993"）属原作致敬，可保留硬编码。

## 7. Godot 最佳实践

### 7.1 节点引用

- 用 `@onready` + `$路径` 缓存节点引用，不要在 `_process` / `_physics_process` 里反复 `get_node()`。
- `$路径` 只在父节点**已就绪**（`_ready` 之后）时才可用，`_init` 里不能用。
- 跨节点引用优先用 `@export` 暴露在 Inspector，少写死路径。

```gdscript
@onready var bodyNode: Node2D = $body
@onready var ani: AnimatedSprite2D = $body/ani
```

> **现状**：`object.gd` 已用 `@onready var bodyNode=$body`，做法正确，补类型注解即可。

### 7.2 生命周期与性能

- 不需要每帧更新的节点，用 `set_process(false)` / `set_physics_process(false)` 关掉回调。
- 移动 / 动画优先用 `Tween`、`AnimationPlayer`，少在 `_process` 里手写插值。
- 计时用 `Timer` 节点或 `await get_tree().create_timer(秒).timeout`，少用自增计数。
- `_process` / `_physics_process` 里避免分配对象（新建 `Vector2(...)`、数组、拼接字符串）。

> **现状**：`stateMachine.gd` 已用 `set_process(enableProcess)` / `set_physics_process(enablePhysicsProcess)` 按需开关，做法正确。
> `playerState.gd` 残留 `print(player.zVec)` 调试输出，应移除或改用 `Engine.is_editor_hint()` 守卫。

### 7.3 资源加载

- 固定路径的资源用 `preload()`（编译期加载，路径写错立即报错）。
- 只有运行期才知道路径的才用 `load()`。
- 频繁复用的场景 / 资源缓存到常量或成员变量，不要每次使用都 `load`。
- 节点引用一律用 `$` / `get_node()`，不要把路径字符串散落在逻辑里。

### 7.4 信号连接

```gdscript
func _ready() -> void:
	$Button.pressed.connect(onButtonPressed)
	Game.enemyDied.connect(onEnemyDied)
```

- 优先在代码里 `.connect()`（便于检索），或使用编辑器「节点 → 信号」面板连接。
- 回调命名统一 `onXxxYyy`（camelCase，不加 `_` 前缀）。
- ⚠️ 若在**编辑器**里连的信号，方法名写死在 `.tscn` 的 `[connection ... method=...]` 里，改名时必须一起改。

### 7.5 安全与健壮性

- 对象可能已被释放时，先用 `is_instance_valid(node)` 判断再访问。
- 节点 `free()` 之后读取它的成员**不会报错，但会静默变 `null`**；需要的数据必须在 `free()` **之前**取出。
- `await` 之后要确认目标仍然有效，再继续操作。
- 释放节点用 `queue_free()`，不要直接 `free()`（除非确定当帧不再使用）。
- 需要下一帧再执行用 `call_deferred()`。

### 7.6 搓招 / 连招系统专属约定

详见 [功能设计.md](功能设计.md) §1。要点：

- 输入缓冲集中在 `InputRecorder` 单例，按 `playerId` 分桶，**不要**在多个脚本里各存一份 inputList。
- 招式定义用 `ComboDef` Resource（`.tres`），**不要**硬编码在 autoload。
- 匹配用后缀严格比较，**不要**用字符串子串 `find`。
- 缓冲衰减用时间戳 + `pop_front()`，**不要**用帧计数 + `pop_back()`。
